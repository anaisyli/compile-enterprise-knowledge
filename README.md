# compile-enterprise-knowledge 企业知识库编译

把筛选过的客户资料编译成可长期复用的两层 Obsidian 知识库，供写文章、建站、CRM 和数字员工共用：

- **来源层**（`02_源资料/10_净化原文`）：净化后的原文，只删不改，每份开头标明来源文件、页码或网址，支持点击“打开原件”。
- **整理层**（`03_正式知识/10_客户知识`）：给人看、也直接给写作 Skill 用的知识页（公司概况、产品、解决方案、FAQ、《公司-速查卡》），每条带 `〔n〕` 链接回原文。

```text
客户资料（邮箱、电脑、客户直发）
  → prepare-seo-knowledge-materials   筛选：哪些能用，哪些要清理
  → compile-enterprise-knowledge      本 Skill：5 阶段建库、智能分流、待办消化、维护与月度体检
  → 任意写作 Skill                     接入 references/writer-guide.md 后，按大纲自动取料、标引用、核对
```

> **长期只需保存两样**：**初筛包**和**知识库**（建议放在 Windows Server 共享盘）。本地运行目录（`--out`）在正式发布后随时可删；配置、决定、冻结提取稿（含 PPT 截图）、OCR 结果、看图核对记录和官网快照都会自动存进知识库 `05_数据与审核/70_构建状态/`，换电脑或增量重建时带 `--vault` 自动恢复。

## 一、建库与续跑（5 个磁盘断点 + Agent 自定节奏）

新建库默认走 `kb_next.py` 进度管理。下面 5 个阶段是**自动落盘的断点，而不是死板强制停顿**：阶段 1 确认时，**AI 会根据本批资料量和自身能力主动建议最稳妥的执行节奏**——资料少可以直接合并阶段 2–5 一口气跑完上线，中等体量可合并其中几步，大画册项目则逐段新开对话防失忆；中途哪怕超时或中断，新开对话发同一句“继续推进”，脚本都会从磁盘精确续跑，绝不重来。

| 阶段 | 自动做什么 | 人做什么 |
| :--- | :--- | :--- |
| **阶段 1：预检分流与一次确认** | **只判断 + 算总页数**（不提取、不整理）：PPT / 画册 / 横版或设计密集 PDF 默认推 **Reducto**，Word 转的规整 PDF / 规格书默认推 **MinerU（免费）**；**前置初判全部 D 类文件**（捞回可用资料并计入页数）；列出《未处理 / 特殊文件清点》并**给出合并/分段执行建议** | 看一眼分流页数、D 类捞回、执行节奏和 5 项建库信息，回 **“同意，按推荐开跑”** |
| **阶段 2：批量提取与抽块** | 抓官网 + 跑 MinerU / Reducto API + 抽块生成来源层和待核对页清单 | 跑完按提示**新开对话** |
| **阶段 3：看图核对** | 一口气核对完 `page-check` 全部页面（页多时自动分给子 Agent 并行），**每 20–30 页增量落盘一次**，中途断了绝不重来 | 跑完按提示**新开对话** |
| **阶段 4：自动消化待办 + 双网页** | Agent 自动消化 90% 的 CUS / MAT / ANM 与待审 D 类，并配合 [customer-confirmation-webpage](https://github.com/anaisyli/customer-confirmation-webpage) **同时生成内部待办决策网页 HTML 和客户确认网页 HTML**（未装该 Skill 时降级输出文字清单与 CSV/JSON） | 内部网页勾选回填（如有）；把客户网页发给客户 |
| **阶段 5：整理正式知识与发布** | 按主题逐个写整理页并落盘 + 速查卡 + 独立子 Agent 抽样通读 + 发布进 Obsidian + 输出最终《未处理 / 特殊文件清点》 | **收库上线**，开始写文章 |

**开工建库 Prompt（不用填运行目录，AI 会自动在本机本地盘创建临时目录）：**
```text
用 compile-enterprise-knowledge 把 <初筛包路径> 建成知识库，官网是 https://www.example.com ，发布到 <知识库路径>。
```

**每段完成后 / 中途中断后的万能续跑 Prompt（直接复制上一轮 AI 给你的续跑句，或新开对话发下面这句）：**
```text
用 compile-enterprise-knowledge 继续推进这个项目：
- 初筛包：<初筛包路径>
- 知识库：<知识库路径>
```

## 二、平时写文章怎么用（内容运营日常）

写作 Skill 完成过一次“接入”（见下方）后，日常写文章**不需要记任何脚本命令**，直接给自己的写作 Skill 发下面任意一种 Prompt：

**1. 指定标题 / 关键词写单篇（最常用）**
```text
用 <你的写作 Skill>，引用知识库 `<知识库路径>` 写一篇英文文章：
- 标题/主题：<文章标题或主题>
- 核心关键词：<关键词 1>、<关键词 2>、<关键词 3>
- 写作要求：<目标受众、词数、其他特殊要求；没有可不写>
- 交付目录：<文章交付输出目录>
```

**2. 只给知识库，让写作 Skill 自己选题写多篇**
```text
用 <你的写作 Skill>，引用知识库 `<知识库路径>` 写 2 篇英文文章。
项目要求/关键词表/选题库在 `<路径>`（没有可不写），最终交付包输出到 `<文章交付输出目录>`。
```

**执行完你会拿到两处结果：**
- **最终文章交付包**（在你指定的交付目录）：纯净的 DOCX、TDK、配图等，不混入任何知识库过程文件；
- **知识库写作记录**（`<知识库>/04_文章任务/10_写作记录/<task_key>/`）：自动沉淀 `大纲.md`、`资料包.md`、`引用表.md`、`核对提示.md` 和给人看的 **`引用追溯.md`**（展示“文章原话 → 知识库哪一节 → 原始资料哪一页 → 引用覆盖率”），并自动登记到 `04_文章任务/00_文章台账.md`。

### 写作 Skill 怎么接入（每个写作 Skill 只做一次）

不改各组写作 Skill 原有的写作流程，只让它们加一小段“知识库接入”**指向本 Skill 的 `references/writer-guide.md`**。以后取料、大纲、引用核对规则升级时，只需更新本 Skill，所有写作 Skill 不用重改。

**把下面这段发给任意写作 Skill 的维护 Agent：**
```text
请给本写作 Skill 加上（或更新）“企业知识库接入（compile-enterprise-knowledge）”一节。只改接入节及下面第 2 条明确指出的两处冲突声明，不要删改、缩写或重写本 Skill 原有的选题、排重、大纲、写作、SEO/GEO、文风、图片、表格、DOCX、QA、发布和交付流程。

1. 先定位本机已安装的 compile-enterprise-knowledge Skill（不要写死版本号或绝对路径），读它的 references/writer-guide.md。
2. 接入一节只写这几条，不要把 writer-guide 的内容抄进来：
   - 什么时候用：本次客户的知识库里有 01_工作台/写作目录.md 时，每次写文章都先读当前已安装 compile-enterprise-knowledge 的 references/writer-guide.md，按它执行大纲落盘、取资料包、写作、标引用与核对；没有写作目录时按本 Skill 原来的方式读资料。
   - 范围锁与写入例外：只用当前请求指定的那一个客户知识库，不读别的客户的知识库或旧对话里的路径；**允许**按 writer-guide 写入 `<知识库>/04_文章任务/10_写作记录/<task_key>/`、更新 `04_文章任务/00_文章台账.md` 以及运行 `research.py`，知识库其余目录严格只读；过程文件不混进最终文章交付包。
   - 解除原文两处冲突：
     a) 本 Skill 原流程里“先读取知识库文档、盘点产品与公司事实”的步骤，在有写作目录时改为“按 writer-guide 先定大纲并落盘锁定，再按大纲取资料包，事实只从资料包里来”；
     b) 如果本 Skill 原文里有“所有输入目录/知识库一律只读、禁止写入任何文件”的规则，明确补充例外：接入 `compile-enterprise-knowledge` 时，上述 `04_文章任务/10_写作记录/<task_key>/`、`04_文章任务/00_文章台账.md` 和 `research.py` 为允许写入位置，不视为违反只读规则。
   - 交付前多一步：按 writer-guide 写极简引用表并运行 check_article.py --citations 生成引用追溯表，按提示改，剩下的写进交付说明。
3. 如果本 Skill 已经有旧的 manage-article-knowledge 接入一节（例如 Enterprise knowledge-base adapter / Strict-mode adapter）：直接删掉，统一替换为本节，不再默认使用 manage-article-knowledge。
4. 改完自检：接入一节只有一份；旧的 manage-article-knowledge 接入一节已删除；里面没有抄 writer-guide 的规则细节；原流程的章节都还在；“先读知识库”和“知识库绝对只读”两处冲突已解除。

完成后告诉我：改了哪个文件、新增还是替换了哪一节、是否已删除旧的 manage-article-knowledge 接入节、是否已解除原文的只读冲突、原流程是否完整保留。不要执行真实写作任务。
```

> **底层写作机制简述**：先锁 `大纲.md` 再用 `kb_lookup.py pack --task` 生成带 `[K#]` 编号的瘦身资料包（超 25 行长表自动折叠可补读）→ 行业公共知识缺口可用 `research.py` 自动调研（每篇最多 2 个，绝不查客户专属事实）→ 写完交 `引用表.md` 跑 `check_article.py --citations` 完成硬事实核对并生成 `引用追溯.md`（只提醒不挡交付，加 `--strict` 可拦）。

## 三、每月自动体检（支持全库 / 部分项目，只读检查）

不需要保留临时运行目录，直接指定 Obsidian 知识库根目录即可一次体检下面所有（或指定几个）项目：每个项目写入各自的 `05_数据与审核/40_月度与交接/知识库体检_YYYY-MM.md`，并在根目录生成一张 **`月度体检总览_YYYY-MM.md`**（汇总本月文章数与平均引用覆盖率、待处理 CUS/MAT/ANM、整理未处理段、外部知识待抽检/过期清单、官网超 31 天提醒、原件/Wiki 断链、索引与本机 MinerU Token；**官网超期只提醒，不自动抓网**）。

**手动一键体检 / 设为每月自动执行的 Prompt：**
```text
用 compile-enterprise-knowledge 对知识库根目录 `<Obsidian知识库根目录>` 做本月月度体检（只读检查，不自动抓官网）：
- 检查范围：<全部项目 / 或填几个项目编号或公司名，如 P-001、P-002>

请运行 `kb_status.py --vault-root "<Obsidian知识库根目录>"`（若指定了部分项目则加上 `--projects`），完成后给我简明汇报：
1. 体检总览（共检查几个项目，🔴 需处理 / 🟡 待关注 / 🟢 正常 各几个；如有未匹配的筛选词请指出）；
2. 逐项列出 🔴 和 🟡 项目的问题重点、负责人与建议动作；
3. 根目录汇总报告位置（全库为 `月度体检总览_YYYY-MM.md`，部分项目为 `月度体检总览_YYYY-MM_部分项目.md`）。
```

- **定时自动跑**：在 Codex Automations 或支持定时任务的客户端里，按**每月最后一个周五 10:00（`Asia/Shanghai`）**新建定时任务，直接粘贴上面这段 Prompt 即可。
- **只体检单个项目**：直接说“用 `compile-enterprise-knowledge` 给 `<单个知识库路径>` 做本月月度体检”（运行 `kb_status.py --vault "<单个知识库>" --monthly`）。

## 五、团队部署：Windows Server 与本机怎么分 + 跨电脑修链接

本 Skill 原生支持 **Windows Server（SMB 共享盘）存长期资产 + 本机本地硬盘跑构建**：已内置 UNC 路径链接适配（`file:///%5C%5Cserver/share`）、跨电脑并发写锁（`.vault.lock`）、SQLite 索引本机缓存读，以及 SMB 不支持硬链接时自动降级为脱敏副本。

| 存放位置 | 放什么 | 说明 |
| :--- | :--- | :--- |
| **Windows Server 共享盘** | `01_Obsidian知识库/`（各项目知识库，含自动沉淀的 `04_文章任务/` 与 `70_构建状态/`）、`02_项目资料与归档/`（初筛包、客户确认 HTML 与回传 JSON/CSV、最终文章交付包） | 全团队共享的长期资产；月度体检直接扫 `01_Obsidian知识库/` |
| **本机本地硬盘（SSD）** | 建库运行目录（`--out`，如 `D:\KB-Workspace\P-001_run`）、初筛 `_working/`、临时内部决策/体检 HTML | **不要把 `--out` 建在共享盘上**；正式发布进知识库后随时可删 |

### 打包发给同事（跨电脑修复原件链接）

如果把**知识库**和**全部初筛包**打包发给同事（打包时跳过初筛包里的 `审计记录/按知识库名字/`，避免体积翻倍），对方放到本地或新共享路径后发下面这段 Prompt 给 AI：

```text
用 compile-enterprise-knowledge（先 git pull 到最新版）帮我修好拷贝过来的知识库链接：
知识库：<知识库文件夹完整路径>
初筛包：<初筛包文件夹完整路径；多个则每行一个>

只做三步，不要重建、不要提取：
1. 试运行：`python scripts/kb_relink.py --vault "<知识库>" --package "<初筛包>" ... --dry-run`，把新旧路径对应和 problems 告诉我，对错了就停下问我。
2. 没问题去掉 `--dry-run` 正式运行。
3. 运行 `python scripts/kb_relink.py --vault "<知识库>" --check`，汇报 file_links、broken、wiki_links、wiki_broken（broken 应为 0）。
```

## 六、知识库目录结构与核心规则

| 位置 | 内容 |
| :--- | :--- |
| `01_工作台/00_知识库总览.md` | **打开先看这个**：有什么、待处理什么、还缺什么、都在哪 |
| `01_工作台/写作目录.md` | 写文章入口：每页的别名、小板块树和字数（写作 Skill 先看这页） |
| `03_正式知识/10_客户知识/` | 整理层知识页（含不超过 2500 字的 `公司-速查卡.md`），每段原文都在覆盖账本中有去处（未处理不为 0 校验不通过） |
| `03_正式知识/20_外部公共知识/` | 外部调研整理的行业公共知识页（只作背景和论据，不代表客户）；证据在 `02_源资料/50_外部调研证据/` |
| `03_正式知识/80_建站资料/` | 可选建站视图：按网站栏目中英对照排列的资料与素材进度 |
| `03_正式知识/90_素材/` | 产品、工厂、证书等图片（只增不删），附《素材索引》和建站用 `00_素材清单.csv` |
| `04_文章任务/00_文章台账.md` | 写过的文章总台账（标题、状态、引用覆盖率、记录链接）；每篇过程文件在 `10_写作记录/<task_key>/` |
| `02_源资料/10_净化原文/` | 来源层原文（按画册、规格书、官网等分目录）；`02_源资料/30_官网快照/` 为官网快照；`源资料与可检索性台账.md` 记每份去向 |

## 七、安装与首次准备（新电脑一次性配置）

### 1. 基础环境与配套 Skill（必装）

1. 安装 **Python 3.10+**，并安装 PDF 读取依赖：
   ```bash
   python -m pip install pymupdf pypdf
   ```
   （PyMuPDF 用于版面分流预检、画册/PPT 分栏读取与原页截图。）
2. 如需读取旧版 `.xls` / `.doc` / `.ppt` 或生成 PPT 幻灯片截图，安装 **LibreOffice**（非默认路径时可设环境变量 `LIBREOFFICE_PATH` 指向 `soffice.exe`）。
3. **配套安装网页生成 Skill（推荐，阶段 4 双网页用）**：安装 [customer-confirmation-webpage](https://github.com/anaisyli/customer-confirmation-webpage)（用于把阶段 4 导出的内部待办和客户 CUS 打包成带原件截图的离线单文件 HTML；未安装时仍可正常输出文字清单与 CSV/JSON）。
4. 运行自检确认环境正常：
   ```bash
   python scripts/check_tools.py
   ```
   > 若 Codex 沙盒拦截 LibreOffice，改用本机终端或非沙盒方式运行提取；临时应急也可把 `.xls/.doc/.ppt` 另存为 `.xlsx/.docx/.pptx` 再放入初筛包。

### 2. MinerU API Token 配置（推荐，免费额度，适合规整 PDF / 扫描件）

> **安全提醒**：Token 只保存在本机 Windows 用户环境变量（`MINERU_API_TOKEN`、`MINERU_API_EXPIRES_ON`），**绝不要把 Token 粘贴进 AI 对话框**，也不要发进群里。

1. 打开 <https://mineru.net/apiManage/token> 登录并创建 API Token，**记下到期日**（`YYYY-MM-DD`），只复制 Token 本身。
2. 进入本 Skill 的 `scripts/` 目录，**双击运行 `setup_mineru.cmd`**。
3. 看到提示后直接按 **Enter**（自动从剪贴板读取并清空，**不要在黑窗口里粘贴**），再输入到期日等待校验完成。
4. **完全退出并重启 Codex / Claude Code** 生效。到期前月度体检会提前提醒，换新 Token 时重新双击覆盖即可。

### 3. Reducto API Key 配置（推荐，按页计费，适合 PPT / 产品画册 / 复杂排版 PDF）

> **安全提醒**：API Key 只保存在本机 Windows 用户环境变量（`REDUCTO_API_KEY`），**绝不要把 Key 粘贴进 AI 对话框**。

1. 打开 <https://studio.reducto.ai/> 登录（新账号一般赠送 15,000 credits），点击 **API Keys → Create new API key**，只复制 Key 本身。
2. 进入本 Skill 的 `scripts/` 目录，**双击运行 `setup_reducto.cmd`**，看到提示后直接按 **Enter** 自动读取并联网校验（只查任务列表，不消耗额度）。
3. **完全退出并重启 Codex / Claude Code** 生效。每次上传前均需人工确认页数并批准后才会调用。
