# compile-enterprise-knowledge 企业知识库编译

把筛选过的客户资料整理成一个 Obsidian 知识库，给写文章、建站、CRM、数字员工共用。

知识库分两层：

- **来源层**：净化后的原文，只删不改，每份开头写清楚来自哪个文件、哪一页、哪个网址。
- **整理层**：给人看的知识页，比如公司概况、产品大类、定制能力、面料工艺、FAQ。每条后面的〔n〕都能点回原文。

## 它在整个流程里的位置

```text
客户资料（邮箱、电脑、客户直发）
  → prepare-seo-knowledge-materials   筛选：哪些能用，哪些要清理
  → compile-enterprise-knowledge      本 Skill：建库、整理、维护
  → manage-article-knowledge（可选）  写文章时按需核验事实
```

不装 manage-article-knowledge 也能用；装了的话，两边用同一套目录结构，互不覆盖。

## 要长期保存什么

只要保存**初筛包**和**知识库**两样。处理过程（运行目录）可以删掉；以后要更新或重建，跟 AI 说“用初筛包和知识库重建”就行，配置、判断结果、台账编号、整理页都会从知识库里恢复。

## 建站资料视图：按网站栏目看客户给了什么

`03_正式知识/80_建站资料/` 按网站的栏目重新排客户资料，栏目名中英对照：

- 首页 Home、关于我们 About Us（企业介绍、工厂与生产、研发、资质认证、展会）、产品 Products、解决方案 Solutions、服务 Services、案例 Cases、资源中心 Resources、博客 / 新闻 Blog & News、FAQ、联系我们 Contact Us，还有待归类 To Sort。
- 产品按客户建站资料里“产品”文件夹的层级排：大类 / 小类 / 产品。同一个产品分几轮给的资料合成一页，按批次列出。
- 每页写：已处理的文件（知识库里的净化原文、打开原件）、官网页面、按类型分的图片、视频、留在初筛包的大图和设计稿、**相关但还没处理的文件**（写原因）、还缺什么。
- 初筛已保留的大图、设计稿和视频算已确认可用的素材，每个写名称、类型、大小、原位置、确认状态，素材索引里也有（素材可能很多，不进台账）；只有要识别文字、转图或等客户确认的才算“还没处理”。
- 总览页 `00_建站资料总览.md` 像网站导航，列出每页的进度。只提取了一部分时也能看：没提取的文件会出现在对应页面的“还没处理”里。
- 归不了的进“待归类”，写原因，不硬分。
- 首页：有 Banner、首页、主图、宣传片标记的直接收；AI 还会从各产品主图里挑候选，标“候选，待确认”，你确认后才算。

归类只看名字（文件夹名、标题），不猜内容。同一个产品的中文名、英文名、几轮资料、型号，写一次产品清单就能合在一起，比如：

```json
"products": [{"name": "DS50系列", "category": "广告机", "sub": "Wall mounted Digital Signage", "aliases": ["DS50系列1", "DS50系列2", "DS50"]}]
```

跟 AI 说“整理产品清单”，它会列出草稿和拿不准的问题（比如编号文件夹是型号还是批次），你确认后写进配置。

已经发布的知识库不用重建也能加上或刷新建站视图：跟 AI 说“只更新建站视图”。它用上次建库的结果重排，只写 `80_建站资料` 这个文件夹，别的都不动，几秒钟就好。

## 打包发给同事

知识库里的正文和 `[[…]]` 链接换到哪台电脑都能用。只有“打开原件”“打开文件夹”“打开对照表”这几种链接写的是初筛包在你电脑上的完整路径，换了位置就点不开，需要对方跑一条命令改过来。

1. 发：知识库项目文件夹（比如 `P-010_…知识库`）和这个项目用到的全部初筛包文件夹（有补充包的也要发，比如 P-010 有 `02_初筛包` 和 `02_补充初筛包-压缩包` 两个；用了哪几个，看知识库 `05_数据与审核/70_构建状态/run-info.json`）。
2. 打包时跳过每个初筛包里的 `审计记录/按知识库名字/`。这里是“打开原件”用的硬链接，在你电脑上不占空间，打进压缩包会变成第二份拷贝（P-010 多出 2.2GB）。对方那边会自动重建。
3. 对方把初筛包放在自己电脑的本地硬盘上（不要放网盘或 U 盘，硬链接建不起来），在 Obsidian 里直接打开知识库项目文件夹作为一个库。
4. 对方运行一次（路径换成他电脑上的位置，几个初筛包就写几个 `--package`）：

   ```bash
   python scripts/kb_relink.py --vault "<知识库项目文件夹>" --package "<初筛包 1>" --package "<初筛包 2>"
   ```

   它会把库里所有指向初筛包的链接改到新位置，重建“打开原件”的硬链接，更新《项目基础信息》和构建记录里的初筛包路径，最后检查一遍链接。
5. 想单独确认链接都能用：`python scripts/kb_relink.py --vault "<知识库项目文件夹>" --check`，会数出“打开原件 / 打开文件夹”链接和 `[[…]]` 链接各有几个打不开。
6. 对方以后要重建，用 `run_pipeline.py --vault <知识库> --package <初筛包>`；跑过 `kb_relink.py` 之后可以不写 `--package`。

**交给 Codex 做的话**，把下面这段发给它，三个尖括号换成对方电脑上的实际位置（只有一个初筛包就删掉“初筛包 2”那行和命令里的第二个 `--package`）：

```text
用 compile-enterprise-knowledge 这个 skill（先 git pull 到最新版）帮我把一个从别的电脑拷过来的知识库修好链接。

知识库：<知识库文件夹的完整路径>
初筛包 1：<第一个初筛包的完整路径>
初筛包 2：<第二个初筛包的完整路径>

只做下面三步，不要重建、不要提取、不要改别的文件：
1. 先试运行（不改东西）：
   python scripts/kb_relink.py --vault "<知识库>" --package "<初筛包 1>" --package "<初筛包 2>" --dry-run
   把输出里的 packages（新旧路径对应）、pages_relinked、originals_linked、problems 告诉我。如果新旧路径对错了，停下问我。
2. 没问题再正式运行（同一条命令去掉 --dry-run）。它会改链接、重建“打开原件”用的硬链接，最后自动检查一遍。
3. 再单独检查一次：
   python scripts/kb_relink.py --vault "<知识库>" --check
   告诉我 file_links、broken、wiki_links、wiki_broken 四个数。broken 和 wiki_broken 都应该是 0；不是 0 的话，把 examples 里的例子贴给我，不要自己改文件。

如果 problems 里说硬链接建不了，原因通常是初筛包放在网盘、U 盘或和原文件不同的盘上，告诉我就行。
```

跑完后在 Obsidian 里随便点一个来源页的“打开原件”，能打开就好了。

## 怎么找原文件

每份资料的来源卡片上都有“打开原件”，在 Obsidian 里点一下就直接打开初筛包里的原文件（用的是初筛包里一个按知识库名字起的硬链接，不复制文件）。第一次建库时，每类文件（画册 PDF、其他 PDF、PPT、Word、Excel、文本、图片）先只提取一份样例，其余的不读。看 `02_源资料/处理计划与样例.md`：每类有几份、怎么提取的、样例是哪份，点样例对照原件看提取得对不对；对了就在“确认状态”一列写“已确认”（或者直接告诉 AI），重跑后这类才批量提取。

知识库里只用改过的名字，比如“产品画册-2027TAPESTRY产品系列”“报价单-322acd78”，不写原文件名，因为原名里常有客户的买家名。原名和新名的对照写在初筛包的 `审计记录/知识库文件对照.md` 里，每次建库自动更新：按知识库名字能找到初筛包里的原文件，按原文件名也能找到它在知识库里叫什么。也可以跟 AI 说“查原件 报价单-322acd78”，它会查出真实路径告诉你。发给客户的确认表用的是原文件名，客户认得出是哪份文件。

## 素材图片给建站用

`03_正式知识/90_素材/` 里的图来自画册 PDF 里的照片、官网页面上的照片、报价单和产品表里的图，还有整页截图。

- **名字说明图是什么**，取自图片旁边的原文，比如 `产品/挂毯/挂毯-Elephant jacquard wall tapestry-1a2b3c4d.jpg`、`产品/2026格子系列/2026格子系列-ANSP-012 SHERPA JACKET-5e6f7a8b.jpg`。不靠猜；买家款号、客户名不进名字。
- **能不能上官网**写在《素材索引》和 `00_素材清单.csv` 里：“可用于官网”来自官网或公司画册；“待核对”是原文有 ⚠ 或名字是 AI 看图起的；“内部”是报价单里的图（多是买家询价发来的款式）和整页截图，不要上官网。
- 清单里还有 alt 文字和英文文件名建议，上传网站时直接用。
- 旁边没字的图先叫“编号”名，可以让 AI 看图补名字。名字定了就不再变，旧的 `img-编号` 图发布时会自动改名，链接跟着改。

**建站资料包里的图片和视频：**初筛时抽看样本、整个文件夹归 A 的图片（渲染图、白底图、实拍图等），直接放进 `90_素材/资料包素材/`，按“大类/产品/图片类型”分文件夹，比如 `资料包素材/广告机/Wall mounted Digital Signage/白底图/…png`；认不出产品的保留原来的文件夹（最后三层）。

- 视频、音频和超过 5MB 的大图不复制进知识库，免得知识库太大；原件留在初筛包里，《素材索引》最后一节按文件夹列出来，点“打开文件夹”就能看。视频内容转写以后才能当知识用。
- 初筛标了“整个文件夹待客户确认”的（比如客户现场照片），客户确认表里只有一行，客户回答一次对整个文件夹生效；回答“保留”后重跑，图片进素材。

## 内容怎么处理

| 内容 | 处理 |
|---|---|
| 价格、成本、数量、联系方式、订单号、竞品、客户名 | 按初筛规则删除，记进《内容清理记录》 |
| 没核实的品牌、明星、IP 名，检测报告页 | **不拦**，入库后标 ⚠，登记 ANM |
| 前后说法不一致的公司数据、款号面料 | 入库，登记 ANM；整理页写“需核实” |
| 客户案例、待客户确认的页面 | 入库后标 🕒，登记 CUS；客户回复前整理页不引用 |
| 产品表、邮件要点 | 入库，状态“待审”；逐格判断加通读后变成“有效” |
| 图片里的字 | 默认 MinerU（免费额度）；读不出内容的整份文件、单张图片可以逐份改成 Reducto；用不了时由 AI 看图转写。读出来的字都标 ⚠ 待核对 |
| 有文字的画册页、PPT、Word 里的图 | 每页先分 A 文字页、B 图文页、C 难页、D 冲突页。B、C 页按“处理方式”读：文字层、MinerU、Reducto 或 AI 看图；款号对不上、读出来不一致的页，再让 AI 对照原图看：补上漏掉的字，标出读错的地方，写清楚款号对应哪款 |
| MOQ、交期、FOB | 公司介绍、画册、官网里照留；只在报价单的行里删，因为那是给某个客户的条件 |
| 报价金额、付款条件 | 删，只删那一句，不删整段 |

来源级别（T1 官方发布、T2 公司文档、T3 产品表、T4 邮件要点）只说明资料从哪来，**不等于每句话都已核实**。

## 能处理的文件

| 文件 | 情况 |
|---|---|
| PDF | 装了 PyMuPDF：按版面分栏读，一页几款时款号跟着它那一栏，每页附原页图；只有 pypdf：按存储顺序读。没文字的页按处理方式走 MinerU、Reducto 或 AI 读图。整份没有文字层的（扫描件）单独成一类“读不出内容”，默认 MinerU |
| pptx | 按文本框位置分栏读；演讲者备注单独一节；每张幻灯片附原图（和 PDF 一样，要 LibreOffice 和 PyMuPDF）；只有图片的页按处理方式走 MinerU、Reducto 或 AI 读图 |
| docx | 正文和表格按顺序读 |
| xlsx | 先分产品清单和报价单；报价单的序号不当款号；所有保留的行再合成一份《产品表汇总》。产品表以外的 Excel 每张表也整理成 Markdown 表，不显示单元格坐标 |
| 初筛标的清理位置 | 只当参考：删不删看整理时的实际内容；初筛标了但其实是产品内容的，保留并标 ⚠，登记 MAT 让人复核 |
| xls、doc、ppt | 用 LibreOffice 转换后处理 |
| md、txt、csv、json、邮件正文 | 正常处理 |
| 客户官网 | 静态页直接读；JS 页面用浏览器读取后导入 |
| 单张图片 | 默认 AI 看图（不上传），可以逐张改成 Reducto（原图上传，每张 1 页）；MinerU 不接单张图片。读出文字后入库并标 ⚠ |
| 初筛按文件夹保留的图片 | 直接进素材库 `90_素材/资料包素材/<大类>/<产品>/<图片类型>` |
| 初筛保留的视频、音频 | 不复制、不转写，在《素材索引》里按文件夹列出，原件在初筛包 |
| ai、压缩包、初筛待定的视频音频 | 不处理，登记待确认或待处理 |

只要有初筛包就行，不需要筛选时的 `_working` 目录。

## 安装

1. 把整个文件夹放进 AI 工具的 skills 目录。
2. 需要 Python 3.10 以上，再运行一次 `python -m pip install pymupdf pypdf`。PyMuPDF 让画册按版面分栏读、附原页图，AI 读图也要用它；不装也能跑，但一页多款的画册款号可能错位。
3. 要处理 `.xls`、`.doc`、`.ppt`，需要装 LibreOffice。装在别的位置时，设置环境变量 `LIBREOFFICE_PATH` 指向 `soffice.exe`。
4. 要用 MinerU 或 Reducto，每台电脑做一次下面对应的设置（Reducto 可选）。
5. 装好后运行一次 `python scripts/check_tools.py`，确认 LibreOffice 真能转换、pypdf 和 PyMuPDF 都在。

**LibreOffice 转换失败怎么办：**

| 现象 | 原因和做法 |
|---|---|
| 以前报“目录不是空的”，或第一次跑失败、第二次又好了 | LibreOffice 退出后还在写临时配置文件，旧版本删不掉就把整份文件记成失败。现在每次转换用一个新的配置目录，删不掉就留着，不算失败 |
| 进程长时间没动静，像卡死了 | 旧版本每个文件最多等 10 分钟、还会重试。现在每个文件最多 2 分钟，超时就结束 LibreOffice 的整组进程；连续 3 个文件失败，其余的不再尝试，直接标“needs_libreoffice”；转换时每个文件打印一行进度 |
| 报 “Io Class:Access” | LibreOffice 没有权限写文件，多半是沙盒挡住了。提取开始前会先试转一个小文件，转不了就直接提示，不会一个个等 |
| `check_tools.py` 在 Codex 里失败、在本机终端里正常 | 沙盒挡住了 LibreOffice。让 Codex 用不受沙盒限制的方式运行提取，或者先在本机终端运行 `run_pipeline.py`，再回到 Codex 继续 |
| 找不到 LibreOffice | 安装 LibreOffice，或设置 `LIBREOFFICE_PATH` |
| 还是不行 | 把 .xls/.doc/.ppt 另存为 .xlsx/.docx/.pptx，放进初筛包再跑 |

## MinerU 首次设置（每台电脑一次）

MinerU 是云端文档解析服务，能识别图片里的文字和表格。资料会上传到 MinerU，所以每个项目上传前都要有人批准。

1. 打开 <https://mineru.net/apiManage/token>，登录团队账号，创建 Token，记下到期日。
2. 双击本 Skill `scripts` 文件夹里的 `setup_mineru.cmd`。
3. 复制 Token 后回到窗口按 Enter。不要把 Token 粘贴进窗口，也不要发给 AI。
4. 输入到期日，格式 `2026-12-31`。脚本会上传一个不含客户信息的测试 PDF，检查整条链路。
5. 看到“设置完成”后，完全退出并重新打开 AI 工具。

| 提示 | 怎么办 |
|---|---|
| Token 缺失或已过期 | 重新创建 Token，再运行一次设置 |
| Token 鉴权失败 | 多半是没复制完整，重新复制后再运行 |
| 额度或频率限制 | 检查账号额度，不是 Token 坏了 |
| 没有联网权限 | 在 AI 工具的权限窗口里允许这条命令联网 |

服务端有时会比登记的到期日更早让 Token 失效，判断以在线检查为准。

## Reducto 首次设置（可选，每台电脑一次）

Reducto 只用来解析难页（图片多的画册、复杂表格、扫描件、单张图片），结果和 MinerU 对照，入库标 ⚠。每个人用自己的 Reducto 账号和 Key，按页计费。

1. 打开 <https://studio.reducto.ai/>，登录后在 API Keys 创建 Key（新账号送 15,000 credits）。
2. 双击本 Skill `scripts` 文件夹里的 `setup_reducto.cmd`。
3. 复制 Key 后回到窗口按 Enter。不要把 Key 粘贴进窗口，也不要发给 AI。脚本会在线验证 Key（不消耗额度），然后清空剪贴板。
4. 看到“设置完成”后，完全退出并重新打开 AI 工具。
5. 想确认整条链路时，运行 `python scripts/reducto_client.py health-check --parse`，会解析一页测试 PDF，消耗 1 页额度。

每个项目上传前，AI 会先给出 `reducto-plan.md`（哪些文件、哪些页、为什么），你同意后它才写批准记录并上传。免费和标准套餐不能主动删除上传的文件，由 Reducto 按保留期清除；要零保留需 Growth / Enterprise 套餐。

| 提示 | 怎么办 |
|---|---|
| Key 缺失或鉴权失败 | 重新复制完整的 Key，再运行一次设置 |
| 额度或频率限制 | 在 Reducto 后台查看余额或升级套餐 |
| 没有联网权限 | 在 AI 工具的权限窗口里允许这条命令联网 |

## 每份文件怎么读（处理方式）

建库后，知识库里有一页“处理计划”，里面有两张表：每一类文件一行（产品画册 PDF、PPT 等），每份文件也可以单独一行。**处理方式**有四种，写在“处理方式”那一格，下次建库读回来：

| 处理方式 | 做什么 | 花钱吗 |
|---|---|---|
| 文字层 | 读文件自带的文字；C 级页交给 MinerU（要批准上传，不能上传时 AI 读图） | 不花 / 免费额度 |
| MinerU 初稿 + AI 复核 | 整份上传 MinerU 出初稿，再让 AI 对照原页图补漏字、标错字 | 免费额度 |
| Reducto 难页 + AI 抽查 | 只把 B、C 级难页上传 Reducto，再让 AI 抽查 | 按页计费 |
| AI 看图复核 | 不上传，AI 看原页图转写并对照文字层 | 不花 |

规则：

- **先每类找一个样例**，样例读得满意再确认这一类，其余文件照样例处理。
- **单个文件可以不一样**：在“按文件指定处理方式”表里改那一行，优先于所在类型。
- **读不出内容的整份文件**（扫描件、全是图的 PPT）类型写“读不出内容”，默认 MinerU。
- **还没识别的单张图片**类型写“单张图片”，默认 AI 看图；MinerU 不接单张图片。
- 写着“（默认）”或“（随类型）”的行原样不动就是没改，不会读回。
- Reducto 的文字是候选：入库标 ⚠；同一页 MinerU 也读了的以 MinerU 为准，两边款号或数字不一致的页交给 AI 看图核对。

## 第一次给客户建库

跟 AI 说一句就行，比如：

> 用 compile-enterprise-knowledge 把 `<初筛包路径>` 建成知识库，官网是 https://www.example.com 。

AI 会按这个顺序做，需要你点头的地方会停下来：

1. 写配置，包括官网产品大类的中文名。
2. 读官网，跑流水线。
3. 判断词清单里的词。
4. 如果画册的字在图片里，列出 MinerU 计划，**等你同意上传**；指定了 Reducto 的文件，另列 Reducto 计划，同样**等你同意上传**。
5. 写整理页，脚本逐条核对出处，也核对写没写全：一页要写到给它的资料的一半以上，产品总览要写到每条产品线。确认过产品清单时，产品页按大类各一页、每个产品一节，同一产品的画册（中英文）、规格书、说明书、官网页面写在一起；没有产品清单时，每本产品画册各有一页产品系列页。
6. 校验，再让另一个 AI 独立通读。
7. 列出五项基础信息，**等你回复“确认建库”**，然后发布。
8. 把《客户确认表》交给你转给客户。

## 日常维护

| 情况 | 跟 AI 说 |
|---|---|
| 客户又发来一批资料 | “先筛选这批新资料，再加进知识库” |
| 客户回复了确认表 | “读回客户确认表，更新知识库” |
| 客户填好了初筛包里的确认表 | “读回初筛包的客户确认表，再建库”。初筛包不用改，回答写进建库的配置 |
| 每月一次 | “给知识库做月度体检，官网重新读一遍” |
| 想查资料 | “在知识库里搜 tapestry jacket，只要公开内容” |
| 初筛拿不准的 D 类资料要处理 | “逐份看 D 类资料”：AI 用 `d_review.py` 列出每份的风险信号，按你定的规则批准、删段、保留、不用或转问客户 |
| 发布前想先看会改什么 | “先试发布看看”：`publish_vault.py --dry-run` 列出会撤下、改名、新增的文件，什么都不写 |

几条规矩：

- **不要手改生成的文件。**要补充就另建一个文件，脚本不会碰它。改了生成的文件，下次发布会停下提醒；Obsidian 自动排版造成的空格变化不算。
- **台账可以填：**台账里的“当前阶段”“下一责任人”可以改，每项下面也可以写“处理记录”，重跑不会冲掉。
- **只增不删：**发布过的资料不再出现时，原位置留“已失效”记录，旧版本自动归档。
- **确认表只给客户：**内部台账在知识库的 `05_数据与审核` 里。

## 已知限制

- 产品表单元格要逐格判断后才算有效，一个中等项目约 2000 个单元格。
- 没有表头、一列混多种信息的工作表还处理不好，会登记在 MAT。
- 整理页要 AI 写、脚本核对；核对只能保证“数字和款号对得上、每条有出处、资料用到一半以上”，概括得好不好还要人看。
- 视频、音频不转写。
- 校验通过不等于没问题，每轮都要独立通读。
