# compile-enterprise-knowledge 企业知识库编译

把筛选过的客户资料整理成一个 Obsidian 知识库，给写文章、建站、CRM、数字员工共用。知识库分两层：

- **来源层**（`02_源资料/10_净化原文`）：净化后的原文，只删不改，每份开头标明来源文件、页码或网址。
- **整理层**（`03_正式知识/10_客户知识`）：给人看、也直接给写文章用的知识页（公司概况、产品、解决方案、FAQ、公司速查卡），每条带 `〔n〕` 链接回原文。

## 它在整个流程里的位置

```text
客户资料（邮箱、电脑、客户直发）
  → prepare-seo-knowledge-materials   筛选：哪些能用，哪些要清理
  → compile-enterprise-knowledge      本 Skill：建库、整理、外部调研、维护、写作取料与核对
  → 任意写作 Skill                     接入 references/writer-guide.md 后，按大纲自动取料、标引用、核对
```

长期只需保存**初筛包**和**知识库**两样。运行目录随时可删；配置、判断、台账编号、整理页、冻结提取稿（含 PPT 截图）、OCR 结果和官网快照发布时都会存进知识库，重建时带 `--vault` 自动恢复。

## 平时写文章怎么发 Prompt（内容运营日常用法）

写作 Skill 完成过一次“接入”（见下一节）后，内容运营日常写文章**不需要记任何脚本命令**，直接给自己的写作 Skill 发下面任意一种 Prompt 即可：

**1. 指定标题 / 关键词写单篇（最常用）**
```text
用 <你的写作 Skill>，引用知识库 `<知识库路径>` 写一篇英文文章：
- 标题/主题：<文章标题或主题>
- 核心关键词：<关键词 1>、<关键词 2>、<关键词 3>
- 写作要求：<目标受众、词数、其他特殊要求；没有可不写>
- 交付目录：<文章交付输出目录>
```

**2. 只给知识库，让写作 Skill 自己选题写多篇**
```text
用 <你的写作 Skill>，引用知识库 `<知识库路径>` 写 2 篇英文文章。
项目要求/关键词表/选题库在 `<路径>`（没有可不写），最终交付包输出到 `<文章交付输出目录>`。
```

**执行完你会拿到两处结果：**
- **最终文章交付包**（在你指定的交付目录）：纯净的 DOCX、TDK、配图等，不混入任何知识库过程文件；
- **知识库写作记录**（`<知识库>/04_文章任务/10_写作记录/<task_key>/`）：自动沉淀 `大纲.md`、`资料包.md`、`引用表.md`、`核对提示.md` 和给人看的 **`引用追溯.md`**（展示“文章原话 → 知识库哪一节 → 原始资料哪一页 → 引用覆盖率”），并自动登记到 `04_文章任务/00_文章台账.md`。

## 写作 Skill 怎么接入（每个写作 Skill 只做一次）

各组的写作 Skill 五花八门，不改它们原有的写作流程，只让它们加一小段“知识库接入”**指向本 Skill 的 `references/writer-guide.md`**。以后取料、大纲、引用核对规则变了，只改 `writer-guide.md`，所有写作 Skill 不用重改。

**把下面这段发给任意写作 Skill 的维护 Agent**（首次接入或同步接入节都用这一段）：

```text
请给本写作 Skill 加上（或更新）“企业知识库接入（compile-enterprise-knowledge）”一节。只改接入节及下面第 2 条明确指出的两处冲突声明，不要删改、缩写或重写本 Skill 原有的选题、排重、大纲、写作、SEO/GEO、文风、图片、表格、DOCX、QA、发布和交付流程。

1. 先定位本机已安装的 compile-enterprise-knowledge Skill（不要写死版本号或绝对路径），读它的 references/writer-guide.md。
2. 接入一节只写这几条，不要把 writer-guide 的内容抄进来：
   - 什么时候用：本次客户的知识库里有 01_工作台/写作目录.md 时，每次写文章都先读当前已安装 compile-enterprise-knowledge 的 references/writer-guide.md，按它执行大纲落盘、取资料包、写作、标引用与核对；没有写作目录时按本 Skill 原来的方式读资料。
   - 范围锁与写入例外：只用当前请求指定的那一个客户知识库，不读别的客户的知识库或旧对话里的路径；**允许**按 writer-guide 写入 `<知识库>/04_文章任务/10_写作记录/<task_key>/`、更新 `04_文章任务/00_文章台账.md` 以及运行 `research.py`，知识库其余目录严格只读；过程文件不混进最终文章交付包。
   - 解除原文两处冲突：
     a) 本 Skill 原流程里“先读取知识库文档、盘点产品与公司事实”的步骤，在有写作目录时改为“按 writer-guide 先定大纲并落盘锁定，再按大纲取资料包，事实只从资料包里来”；
     b) 如果本 Skill 原文里有“所有输入目录/知识库一律只读、禁止写入任何文件”的规则，明确补充例外：接入 `compile-enterprise-knowledge` 时，上述 `04_文章任务/10_写作记录/<task_key>/`、`04_文章任务/00_文章台账.md` 和 `research.py` 为允许写入位置，不视为违反只读规则。
   - 交付前多一步：按 writer-guide 写极简引用表并运行 check_article.py --citations 生成引用追溯表，按提示改，剩下的写进交付说明。
3. 如果本 Skill 已经有旧的 manage-article-knowledge 接入一节（例如 Enterprise knowledge-base adapter / Strict-mode adapter）：直接删掉，统一替换为本节，不再默认使用 manage-article-knowledge。
4. 改完自检：接入一节只有一份；旧的 manage-article-knowledge 接入一节已删除；里面没有抄 writer-guide 的规则细节；原流程的章节都还在；“先读知识库”和“知识库绝对只读”两处冲突已解除。

完成后告诉我：改了哪个文件、新增还是替换了哪一节、是否已删除旧的 manage-article-knowledge 接入节、是否已解除原文的只读冲突、原流程是否完整保留。不要执行真实写作任务。
```

## 写文章时的取料、引用核对与外部调研（底层机制）

写作 Skill 按 `references/writer-guide.md` 自动执行以下步骤：

1. **先锁大纲，再取资料**：定大纲时不读知识库，落盘到 `<知识库>/04_文章任务/10_写作记录/<task_key>/大纲.md` 并标 `outline_status: 已确认`；再看 `01_工作台/写作目录.md` 填好 `## 资料对应` 和 `## 缺口`，运行 `python scripts/kb_lookup.py pack --task "<大纲.md>"` 生成带 `[K1]`、`[K2]` 编号的 `资料包.md` 和 `资料包.json`。
2. **自动瘦身与补读**：去掉长链接和来源列表，超过 25 行的长表自动折叠并附补读命令（编号前缀 `R`）；加 `--budget <字数>` 时只做不丢事实的压缩（折 >10 行表、去未整理线索）。
3. **写完核对与引用追溯**：写作 Skill 交极简 `引用表.md`（`文章原文 | K12, K15`），运行 `python scripts/check_article.py --article <终稿> --pack 资料包.md --citations 引用表.md --vault "<知识库>"`，几秒钟完成硬事实核对（三层规则在 `assets/check-rules.json`，支持自动识别行业、中英文单位等价归一、以及从当前知识页自动收集单位与牌号），输出给人看的 `引用追溯.md` 并回写 `04_文章任务/00_文章台账.md`。只提醒不挡交付（要挡加 `--strict`）。
4. **外部调研（只补行业公共知识）**：
   - **按缺口批量补**：`research.py plan --vault <库> --from-gaps` → 勾选 `plan.md` → `approve` → 调研 → `collect`。
   - **按文章缺口自动补**：`research.py plan --vault <库> --from-outline "大纲节;…"`（每篇最多 2 个缺口，库里已有直接复用）。
   - **边界**：只查标准、原理、材料、选型等行业公共知识，**绝不查客户专属事实**（产能、证书、案例、交期、MOQ、价格、保修），排除竞品/同业厂商/论坛/AI 站，数字需至少 2 个非百科来源；结果入 `20_外部公共知识/`（标“待抽检”，月度体检时用 `research.py status / mark` 抽检复查）。

## 整理层完整性：整理覆盖账本

整理页要做到写文章时平常不用回原文，所以本主题所有可用原文分批交给 AI（不按 40 段硬截断），每一段都必须有去处：

- **写进**（`{{src:块}}`）：写成要点，数字与款号原样出自原文。
- **原样表**（`{{表:块}}`）：脚本原样搬表（AI 不手抄），超 25 行自动折叠为表头+行数+原文链接。
- **指针**（`{{见原文:块}}`）：超长工程表、历史条款等写一句话说明加原文链接。
- **重复 / 不需要写**：记入 `ledger.jsonl`（含型号、数字、标准号、年份的段禁止标“不需要写”）；纯噪音和完全重复由脚本自动处理；漏网段进 `unsorted` 待归类批次。

覆盖与缺口页顶部汇总每页去处统计，**“未处理”不为 0 时校验不通过**（旧库过渡期可在 `kb-config.json` 临时设 `"curation": {"ledger": "warn"}`）。每页顶部写中英文 `别名：`，另配一张 ≤ 2500 字的《公司-速查卡》。

## 建库、增量重跑与日常维护

### 常用 Prompt 速查

| 场景 | 直接发给 AI |
|---|---|
| 第一次建库 | “用 compile-enterprise-knowledge 把 `<初筛包路径>` 建成知识库，官网是 https://www.example.com 。”（每类文件先抽 1 份样例，确认处理方式后再批量提取） |
| 客户补发新资料 | “先筛选这批新资料，再叠加进 `<知识库路径>` 重跑发布。”（旧文件按原件哈希冻结复用，不重提） |
| 回填客户 CUS 回复 / 批准 D 类 / 改词表 | “读回客户确认表 `<路径>`，用 `--from guard` 更新知识库。”（跳过提取，不动旧提取稿和 PPT 截图） |
| 只改整理页 / 补别名 / 改速查卡 | “用 `--from curate` 重跑整理层并发布。”（不动来源层和 PPT 截图） |
| 定点重提某份有问题的文件 | “用 `--re-extract <item_id>` 只重提这一份文件。” |
| 建站资料视图（可选） | “只更新建站视图”或“整理产品清单”（按网站栏目中英对照生成 `03_正式知识/80_建站资料/`） |
| 按缺口做外部调研 | “按知识库缺口做外部调研，先给我看建议清单。” |
| 每月体检 | “给知识库做月度体检，官网重读一遍，顺便看外部公共知识的待抽检和过期页。” |
| 发布前预览改动 | “先试发布看看（`publish_vault.py --dry-run`），什么都不要写。” |

### 核心规则速览

- **内容清理与风险分级**：价格、成本、数量、联系方式、订单号、竞品、客户名按规则删除（记《内容清理记录》）；未核实品牌/IP、检测报告页、冲突口径不拦，标 `⚠` 登记 ANM，整理页写“需核实”；待客户确认内容标 `🕒` 登记 CUS；来源级别（T1–T4）只表示出处，不等于已核实。
- **文件读取与处理方式**：每类文件先看样例（`02_源资料/处理计划与样例.md`），可选 `文字层`、`MinerU 整份 + AI 核对`（免费额度）、`Reducto 整份 + AI 核对`（按页计费）、`AI 看图复核`；尺寸图只记型号和图名，不抄尺寸标注。
- **素材与原件**：`90_素材/` 按来源命名且只增不删，标注“可用于官网 / 待核对 / 内部”；超 5MB 大图与视频留在初筛包并在《素材索引》登记；“打开原件”走脱敏硬链接，原名对照在初筛包 `审计记录/知识库文件对照.md`。
- **增量冻结与只增不删**：已确认的提取稿（`package-text/`）与 PPT 截图（`extracted-assets/`）发布时冻结进 `70_构建状态/`，重跑默认沿用上次的 `--images` / `--tiers` 且不重提未变原件；不要手改生成的整理页（补充另建文件），台账的人工列可填且重跑保留。

## 打包发给同事（跨电脑修复原件链接）

发给同事时，把**知识库文件夹**和**全部初筛包**（见 `70_构建状态/run-info.json`）一起发，打包时**跳过**初筛包里的 `审计记录/按知识库名字/`（硬链接，打包会变双倍体积）。对方放到本地硬盘后运行（或把下面这段发给 AI）：

```text
用 compile-enterprise-knowledge（先 git pull 到最新版）帮我修好拷贝过来的知识库链接：
知识库：<知识库文件夹完整路径>
初筛包：<初筛包文件夹完整路径；多个则每行一个>

只做三步，不要重建、不要提取：
1. 试运行：`python scripts/kb_relink.py --vault "<知识库>" --package "<初筛包>" ... --dry-run`，把新旧路径对应和 problems 告诉我，对错了就停下问我。
2. 没问题去掉 `--dry-run` 正式运行。
3. 运行 `python scripts/kb_relink.py --vault "<知识库>" --check`，汇报 file_links、broken、wiki_links、wiki_broken（broken 应为 0）。
```

## 安装与首次配置

1. Python 3.10+，安装 `python -m pip install pymupdf pypdf`（PyMuPDF 用于 PDF 分栏读取和原页图）。
2. 处理 `.xls` / `.doc` / `.ppt` 及 PPT 幻灯片截图需安装 LibreOffice（自定义路径可设环境变量 `LIBREOFFICE_PATH` 指向 `soffice.exe`）。装完运行 `python scripts/check_tools.py` 验证；若 Codex 沙盒拦截 LibreOffice，改用本机终端或非沙盒方式运行提取。
3. **MinerU（免费额度，可选）**：在 <https://mineru.net/apiManage/token> 创建 Token → 双击 `scripts/setup_mineru.cmd` → 复制 Token 回窗口按 Enter（勿发给 AI）→ 输入到期日 → 重启 AI 工具。
4. **Reducto（按页计费，可选）**：在 <https://studio.reducto.ai/> 创建 Key → 双击 `scripts/setup_reducto.cmd` → 复制 Key 回窗口按 Enter → 重启 AI 工具。上传前均需人工批准计划。
