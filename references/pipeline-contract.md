## 长期保存什么

处理完成后只长期保存两样东西：**初筛包**和 **Obsidian 知识库**。运行目录是可以随时删掉的缓存。所以凡是重建或维护要用到、又不能从初筛包重新算出来的东西，发布时都要写进知识库：

| 内容 | 知识库里的位置 |
|---|---|
| `kb-config.json` | `05_数据与审核/70_构建状态/kb-config.json` |
| 词的判断 `review-decisions.json` | `05_数据与审核/70_构建状态/` |
| 产品表逐格判断（判断记录、表格模板判断、通读记录） | `05_数据与审核/70_构建状态/cell-review/` |
| 台账编号 `governance-ids.json` | `05_数据与审核/70_构建状态/` |
| AI 写的整理页原稿 `page.md` | `05_数据与审核/70_构建状态/curation/<主题>/page.md` |
| 客户回答备注 `client-notes.jsonl` | `05_数据与审核/70_构建状态/` |
| MinerU 识别结果 | `02_源资料/20_MinerU按需提取/` |
| 官网快照（页面清单和每页正文） | `02_源资料/30_官网快照/` |
| 素材图片 | `03_正式知识/90_素材/` |
| 图片名字 `picture-names.json`、AI 看图起的名字 `picture-names/answers.json` | `05_数据与审核/70_构建状态/` |
| 官网图片清单 `website/pictures.json` | `02_源资料/30_官网快照/pictures.json` |

- `run_pipeline.py` 增加 `--vault <项目目录>`，这时 `--package` 和 `--config` 可以不写，默认用知识库里记录的上次的初筛包和配置。开跑前先把上面这些从知识库恢复到运行目录；运行目录里已有较新的版本时，以运行目录为准，并提示一句。
- **配置和各种判断按条合并，不整份覆盖：**`kb-config.json`、`sample-decisions.json`、`site-home.json` 这类 JSON 对象，恢复和发布时按顶层条目合并：只有一边有的条目保留（比如人写进知识库的 `products`、`site_sections`）；两边都有、内容不同时用较新那份的，并在提示里写出是哪几条。合并后两边一样。以前整份按“谁新用谁”，运行目录里一份较晚改过、但没有产品清单的配置，会把知识库里的产品清单整份盖掉。其他文件（整理页原稿、MinerU 结果等）仍按较新的那份。
- 第一次建库时配置还在运行目录；发布后，知识库里的那份就是正本。
- 判断标准：删掉运行目录后，用“初筛包 + 知识库”重建，生成的来源层、整理页和台账要和删除前完全一致，台账编号也不变。
- 能从初筛包重新算出来的（提取文字、转换后的旧格式文件、内容块）不进知识库。

## kb-config.json

```json
{
  "project_id": "P-007",
  "company": "公司全称",
  "own_terms": ["公司的中英文名、简称、自有款号前缀"],
  "style_prefixes": ["NTXP", "NTX"],
  "own_domains": ["公司邮箱和官网域名"],
  "own_contacts": ["公司公开电话，写成文中出现的样子"],
  "deny_terms": ["竞品和第三方名称"],
  "vocabularies": ["apparel"],
  "websites": [{"url": "https://www.example.com", "role": "primary"}],
  "categories": {"tapestry-jacket": "提花夹克"},
  "doc_titles": {"<item_id>": "产品画册-2027 提花系列"},
  "mineru": {"approved": true, "approved_by": "姓名", "approved_at": "YYYY-MM-DD", "scope": "本计划全部文件"},
  "header_map": {"面辅料信息": "fabric"},
  "sheet_columns": {"<模板签名>": {"B": "style"}},
  "client_answers": {"<item_id>": "keep"},
  "client_answers_units": {"<item_id>": {"第 4–5 页": "drop"}}
}
```

- `kb-config.json` 发布后存进知识库的 `05_数据与审核/70_构建状态/`，以后改配置就改那一份。

- `categories`：官网网址第一段对应的中文大类，用于标题和文件夹。只用于导航，不算事实。
- `doc_titles`：想手动定的来源文档标题，格式“类别-名称”。
- `doc_roles`：纠正“参考整理稿”的自动判断，`{"<item_id>": "reference"}` 或 `"original"`。
- `skip_topics`：决定不写的整理主题和理由，比如 `{"faq": "原文里问答太少"}`，主题编号见 `curation/topics.json`。
- `sections`：按模块调整小板块。同名的整体替换，新名字加在后面，`"remove": true` 删掉。例如：
  `{"company": [{"name": "环保", "keywords": ["recycled", "再生"], "how": "向客户要环保认证"}, {"name": "销售市场", "remove": true}]}`。
  模块名用 company、product、solution、case、industry、faq、other。
- `vocabularies` 选用 `assets/vocabulary-<行业>.txt`。词表只放行业通用词，不放客户名、品牌名或款号前缀。
- `client_answers` 和 `client_answers_units` 一般由 `apply_answers.py` 写。它读建库的 `客户确认表.csv`，也读初筛包的 `客户确认表.xlsx`（`--answers` 给 .xlsx 路径，按表头找列，Excel 或 WPS 存过的都能读）。初筛表的编号这样对应：
  - `<item_id>#<n>`：位置是整份文件，或不在该文件的 `pending_units` 里，写 `client_answers[item_id]`；否则写 `client_answers_units[item_id][位置]`。
  - `folder:<文件夹>`：写给 manifest 里 `review_group` 是这个文件夹的每个文件。
  - 知识点编号：写 `client_answers[knowledge_id]`。待客户审核的知识点，回答“保留”后进业务要点。
  - 读不懂或找不到的编号列在输出的 `unclear` 里。“需要修改”和备注只记进 `client-notes.jsonl`。

## review-decisions.json

```json
{"allow_terms": ["普通词"], "deny_terms": ["确认的客户或竞品"], "keep_blocks": ["block_id"], "drop_blocks": ["block_id"]}
```

`keep_blocks` 只能放行“可能是客户名”和“没核实过的词”，不能放行价格、贸易条款、订单号和外部联系方式。

## 入库判断

| 来源 | 去向 |
|---|---|
| A 类 PDF、PPT 宣传资料 | T1，入库 |
| A 类其他文档 | T2，入库 |
| A 类整份待客户确认 | 入库，整份标“待客户确认” |
| A 类图片 | 先不入库，登记 CUS；MinerU 或 AI 读图读出文字后，作为 T2 入库，标 ⚠ |
| B 类 | B 只说明要清理，不说明是什么文件，按文件实际内容处理：Word、PDF、PPT、文本按文档读正文，级别和 A 类一样（宣传用 PDF/PPT 为 T1，其余 T2）；工作表有产品表头的按产品表逐行清理，成为 T3、默认“待审”，没有产品表头的按整张表保留并标 ⚠。初筛的清理标记只当参考；只删作者、模板这类文件属性的标记直接忽略（知识库不带文件属性），找不到位置的登记 MAT。原文件名里有客户名或禁用词时，标题换成编号 |
| C 类 | 知识点入库，T4，默认“待审” |
| D 类 | 不入库，登记 MAT；客户回答“保留”后入库 |
| E、竞品、SEO 运营、受限、重复 | 不入库，只在资料台账里计数 |
| 官网页面 | T1；客户案例页标“待客户确认”；分类列表页、重复页跳过 |

不是初筛包的文件夹一律拒绝。只给初筛包时自动提取文字，先核对哈希，被改过的文件不读；超过三成该入库的资料读不到文字，并且读不到的确实占多数时，校验失败。

## 筛查结果

每个内容块只有一种结果：

| 结果 | 什么内容 | 怎么处理 |
|---|---|---|
| 删除 | 报价金额、成本、付款条件、订单号、外部邮箱或电话、竞品、可能的客户名、被删问题的答案；产品表的行里另加：数量或包装、单耗、业务备注、给客户的报价条件（MOQ、交期、FOB 等） | 不入库，记进《内容清理记录》 |
| 标记入库 | 没核实过的词（可能是品牌、明星、IP）、检测或审核报告页、AI 看图转写的文字 | 入库，原文旁标 ⚠ 和 ANM 编号 |
| 待客户确认 | 初筛标记的页或节、整份待确认的文件、官网客户案例页 | 入库，标 🕒 和 CUS 编号；整理页不引用 |
| 保留 | 其他 | 入库 |
| 丢弃 | 乱码、空块、只有标题的网页段落 | 不入库 |

没核实过的词：表格行和识别出的文字检查全部英文词；官网正文只检查首字母大写或带数字的词，在全站超过 5% 页面出现的词视为网站自己的常用词。

**删多大范围：**
- 正文按句删：一段话里只有一句报了价，只删这一句，其余照留。切开的几句按原顺序放，合起来仍和原文一字不差。
- 表格按行删：一行里有任何一格命中，整行删掉。
- 价格词要带金额才算：“单价 6.8”“报价 USD5”删；“价格有竞争力”“价格阶梯起点须分别确认”不删。
- MOQ、交期、FOB 这类在公司介绍、画册、官网里照留，因为公司本来就会公开写。只有在产品表或报价单的行里（给某个客户的报价条件）才删。
- 付款条件（T/T、L/C、定金、尾款、付款方式）一律删。
- 不要把“正式成立”“Established in”这类说法写进 `deny_terms`。成立年份说法不一致会自动登记 CUS 问客户，不需要删原文。

**检测或审核报告页：**PDF 的页、PPT 的幻灯片命中就整页标 ⚠；Word 这类不分页的文档只标提到报告的那一段，不会因为提到一次报告就把整章标上。

**参考整理稿：**文件自己写着“内部审核版”“draft”“公开参考”“参考款”“参考供应商”“仅供参考”这类话，出现 3 次以上时，认作参考整理稿：从别家公开资料或旧稿整理的参考，不是公司自己的资料。
- 入库可检索，状态“参考稿”，卡片上写明；每段带 `reference_draft` 标记，登记 ANM。
- 整理页引用时必须带 ⚠，只能写成“参考资料显示……（待公司确认）”；选原文时排在公司自己的资料后面。
- 判断错了在 kb-config.json 的 `doc_roles` 里改：`{"<item_id>": "original"}` 或 `"reference"`。

**产品表里的品牌词：**产品表的款号、品名、描述格里，首字母大写、不带数字、谁也没核实过的词（比如某零售商的自有品牌名），通常是客户自己的品牌。这一格隐去，其余格照留，行旁标 ⚠，词进待判断清单；确认是普通词就写进 `allow_terms`，下次重跑会显示出来。只剩品牌、没有描述、面料、款号的行不入库。

## 来源层

- **标题“类别-名称”：**
  - 产品画册：“产品画册-…”；公司文档：“公司资料-…”。
  - 产品表：“产品表-<哈希>”；报价单（表头有单价、数量、金额、MOQ 这类列）：“报价单-<哈希>”，放在 `产品表/报价单/`；邮件要点：“业务要点-邮件摘录”。
  - 官网产品页：“<大类>-<产品名>”；官网其他页：“官网-<页面名>”。
  - 文件名里的“(1)”、时间戳、“副本”、“- 公司名”后缀都会去掉。
  - 文件名本身说明不了内容的（页面文本、新建文本文档、未命名、index、readme 等），后面加上所在文件夹的名字，比如 `关于我们/页面文本.txt` 叫“公司资料-页面文本-关于我们”，几十个同名文件不会只靠编号区分。
- **同一份资料两种格式只入库一份：**同一个文件夹里名字相同、只是格式不同的 Word / PPT 和 PDF（比如 `规格书.docx` 和 `规格书.pdf`），是同一份资料另存的 PDF。只读 Word / PPT 那份（原件，文字准确），PDF 记为不入库，原因“同一份资料的另一种格式”（`routes.json` 里 `reason: other_format`，`same_as` 写保留的那份）。保留页的来源卡片写“同一份资料还有 PDF 版：[打开原件](…)”，PDF 也在 `审计记录/按知识库名字/` 下用保留页的名字建硬链接；对照表里 PDF 一行指向保留的那页。Word / PPT 读不出文字时，PDF 照常入库。样例不挑这种 PDF。已发布过的 PDF 那页（文件名带 `_xxxxxx` 的那份）下次发布时移进版本归档，版本说明里记为改名到保留页，不算已失效，也不会触发“很多资料同时失效”的停止。
- **来源卡片：**
  - 初筛包名、资料编号（初筛包审计记录里的 `item_id`）、页数、抓取时间、SHA-256；官网页面写原标题和网址。
  - 来源级别（注明不等于已核实）、状态、相关事项编号。
- **原文件名只在初筛包里：**
  - 知识库里只用改过的名字（上面的“类别-名称”），任何页面、台账都不写原文件名，因为原名里常有客户的买家名。
  - 每次建库在每个初筛包的 `审计记录/知识库文件对照.md` 和 `.csv` 里写一张对照表：知识库名字、知识库位置、初筛包里的位置（原名）、初筛类别、去向、资料编号。A–D 类每份一行，E 类只计数。这是本 Skill 唯一写进初筛包的东西，原件、清单、manifest 都不动。
  - 知识库名字和原文件名不一样是正常的，不算错误。公司自己的名字（比如公司简称）可以出现在知识库名字里，要藏的只是公司的买家和零售商。
  - 台账里提到没入库的文件时，写资料编号，原名去对照表里查。
- **一键打开原件：**每份入库资料在初筛包的 `审计记录/按知识库名字/` 下有一个用知识库名字命名的硬链接，比如 `报价单-0a663a2b.xls`：同一个文件，不复制、不占空间。来源卡片、资料台账、处理计划页的“打开原件”链接到它，在 Obsidian 里点一下就用原来的软件打开原件；链接里只有知识库名字，没有原文件名。做不了硬链接时（初筛包在别的盘、U 盘或网络盘），这一份没有链接，按对照表查。
- **处理计划与样例：**`02_源资料/处理计划与样例.md`，每次构建更新。
  - 按文件类型分行：产品画册 PDF、其他 PDF、PPT、Word 文档、Excel / CSV 表格、文本、单张图片、邮件知识点、官网页面。每行写份数（包括还没提取的）、在初筛包哪个文件夹（只到文件夹）、怎么提取（读完以后发现的报价单、产品表、参考整理稿也写在这里，比如“其中 79 份是报价单”）、样例、样例情况、要做的事（确认后提取其余几份、看图核对几页、几页要读图）、处理方式和确认状态。
  - **样例情况**（PDF、PPT）：样例共几页、几页没有文字层、对照原图看了几页其中几页图里有字文字层没有、几页文字层有错、几页看不出款号对应；试读过 MinerU 的，写 MinerU 多读出了几页。据此给建议：有无文字页，或者看过的页里两成以上有漏字或错字，建议“MinerU 初稿 + AI 复核（不想上传就选 AI 看图复核）”；否则“文字层够用”。还没对照原图看的，提示先做看图核对。
  - **处理方式**（PDF、PPT）：文字层（默认）、MinerU 初稿 + AI 复核、AI 看图复核。人在这一列写选择，和确认状态一起在发布时读回，存进 `sample-decisions.json` 的 `method`；写着“（默认）”的不算选择。旧版按“报价单”“产品清单表格”确认过的，算 Excel / CSV 已确认。
  - **先提取样例，确认后再批量提取：**`run_pipeline.py` 开头运行 `sample_gate.py`，只看初筛包清单、不读文件，按扩展名（PDF 再按是不是画册）分类，每类挑一份大小居中的做样例（配置里 `samples` 可以按类型指定资料编号），写 `04_知识库构建/sample-gate.json`。没确认的类型只提取样例：`extract_package_text.py` 不读其余文件，`extract_blocks.py` 把它们记为“等样例确认后提取”（不算读不到文字），`ai_read.py`、`page_check.py`、`mineru_ocr.py` 也只处理样例。确认后重跑，这类全部提取。网页和邮件知识点不在这一步。
  - 看图核对认出的结构另列一张表，每种结构一行，样例链接到那一页。
  - 最后列不处理的资料：初筛类别、原因、份数。
  - “确认状态”人可以直接改成“已确认”或“要改：……”；发布时读回来，存进 `70_构建状态/sample-decisions.json`，下次构建照此执行，不会被覆盖，也不会因为人改过而停止发布。
  - 没确认的类型，看图核对只列样例那一份的页；校验提醒还有几类没确认。用户明确说不用看样例时，配置写 `"sample_review": false` 关掉这一步，全部直接提取。
  - 总览页“资料从哪里来”链接到这一页。
- **客户确认表用原文件名：**`客户确认表.csv` 每行有“原文件名”和“在初筛包里的位置”，客户认得自己的文件。这张表只放在运行目录里交给客户，不发布进知识库。
- **查原件：**`find_source.py --package <初筛包> --id <知识库名字或资料编号>` 先查对照表，再查 manifest，打印真实路径和哈希是否一致，只在终端里显示，不写进知识库。用户说“查原件 报价单-322acd78”时，AI 就运行它。
- **版面：**PDF 和 PPT 按版面读，见“各类文件怎么读”。分栏读的资料，卡片上写一句版面说明；没装 PyMuPDF 时卡片提示“按存储顺序读取，一页多款可能错位”。
- **原页图：**装了 PyMuPDF 时，不超过 80 页的 PDF 每页、不超过 80 张的 PPT 每张幻灯片都附一张缩略图，放在页或幻灯片标题下，方便对照原件。删过内容或有待客户确认内容的页不附，因为图上能看到被删的东西。
  - PPT 先用 LibreOffice 转成 PDF 再截图，顺序按演示文稿里的放映顺序，隐藏的幻灯片不算；转出的页数和幻灯片数对不上时整份不附图，免得图配错幻灯片。PPT 里印的照片也按 PDF 的规则收进素材。
  - 没有 LibreOffice、没装 PyMuPDF 或转换失败时，文字照常全部读取，只是没有截图；校验报告提示“PPT 没有幻灯片截图”和原因，装好后重跑就会补上。
- **产品表汇总：**`产品表/00_产品表汇总.md` 把所有产品表和报价单里保留下来的行合在一起，同一款号（没有款号的按描述和面料）只列一次，每行链接回原表，状态跟原表一致。
- **资料台账（《源资料与可检索性台账》）：**
  - 最上面是“初筛包处理对照”：A–E 每类和官网页面各一行，写包内有几份、入库几份、入库后各状态几份、几份几页图片待识别、暂缓几份（原因）、不入库几份（原因）。C 类写“N 份→汇总成 1 份《业务要点》”。E 类只计数，不列文件名。
  - 下面每份入库资料一行，含提取完整度：页数、待识别页（具体页码）、规则删掉了几段、占多少。
  - 总览页的“资料从哪里来”链接到这里。
- **状态：**有效、待审、待客户确认、部分待客户确认、已失效。
- 标题命中价格、条款等禁止内容时，改用“类别-编号”。

## 台账

格式参照 manage-article-knowledge，编号形如 `P-007-CUS-001`，跨次运行不变。**一个问题只在一个地方出现。**

| 台账 | 登记什么 | 谁来解决 |
|---|---|---|
| CUS 待客户补充事项 | 所有要客户回答的：待确认的页、节、文件、官网案例页；产品图能否公开；公司数据、款号面料以哪个为准 | 客户 |
| MAT 源资料处理台账 | 资料要处理的：要 MinerU 识别、提取失败、找不到表头、款号列疑似放错、要用浏览器读取的页面、官网没读到、清理位置看不懂、规则删得多的资料（画册和公司资料里删掉超过两成段落）、产品表逐格判断进度 | 内部 |
| ANM 源文与事实异常台账 | 内部要判断的风险：已生效资料（画册、官网、公司资料）里没核实过的词、检测或审核报告页、AI 看图转写的页 | 内部 |

**合并规则：**同一原因、同一责任人、同一关闭条件的事项只记一项，详情里列出全部涉及内容。比如：
- 5 个官网案例页合成一项。
- 同一份文件里待确认的几个章节合成一项。
- 待审产品表里的生词不进 ANM，由 MAT 的“产品表逐格判断”一项覆盖。

**写法：**
- 主表只放短字段：编号、一句话问题（30 字以内）、涉及数量、当前阶段、下一责任人、最近更新。长内容一律放进“事项详情”。
- 问题要写具体，不写“见 ANM-003”这种跳转。比如：“23 个款号在不同报价表里面料写法不同，请确认以哪个为准”。
- 冲突类事项的详情用表格：款号或项目 / 写法 A（来源链接）/ 写法 B（来源链接），每格最多 80 字，超出的写“…”并给链接。
- 公司数据（成立年份、员工人数等）的每个值都附一小段原文（不超过 40 字）和出处。

**检测规则：**
- 成立年份：只认紧挨“成立 / 创立 / 建厂 / established / founded”的年份；“since”不算；今年及以后的年份不算。
- 员工人数：只认紧挨“员工 / 工人 / employees / workers”的数字。
- 款号面料冲突：款号必须像编号（不超过 20 个字符、不超过 3 个词）。像描述的“款号”说明列识别错了，登记 MAT“款号列疑似放错”，不算冲突。

**人填的内容要保留：**台账允许人改“当前阶段”“下一责任人”，也允许在每项详情下加 `#### 处理记录`。重新生成台账时按编号合并：保留这些人填的内容，只更新机器生成的部分。机器认为已解决、但人没关的事项，阶段写“系统已解决，待确认”，不直接删除。

- 《内容清理记录》按原因、按资料列出删除了多少段、在哪个位置，不重复原文。
- `客户确认表.csv` 只放 CUS 的问题，每行写清楚问题和涉及内容，交给客户。

## 覆盖与缺口

每次发布生成 `05_数据与审核/20_知识库覆盖与缺口/01_知识库覆盖与缺口.md`，按七个模块列出：
- 有哪些整理页、多少份来源文档。
- 每个小板块一行：原文段数（重复的只算一次）、来源份数、状态、怎么补。状态分五种：
  - 有：原文和整理页都有。
  - 薄弱：原文少于 3 段，或只有一份来源。产品总览里每本画册各占一节，一节本来就只有一份来源，所以只看段数。
  - 有原文没整理：原文有，整理页里没有这一节的 `##` 标题（或单独成页的那页没写）。
  - 缺：一段原文也没有；“怎么补”写分类表里的建议，比如向客户要证书。
  - 决定不写：主题写进了 `skip_topics`，整个主题只占一行，理由写一次，汇总时按小板块个数计。
- 缺口只列在这一页，不写进 CUS 台账。
- 哪些“有效”来源文档没被任何整理页引用。意思是原文已入库、能检索，但读整理页的人看不到它；要补写对应主题，或在整理页里引用。
- 哪些模块是空的，以及原因，比如合作案例要等客户确认。
- 已准备、还没写的主题。
- 还没识别的图片页（份数、页数）。

总览的“还缺什么”写一行小板块汇总，比如“有 12，薄弱 6，有原文没整理 3，缺 7”，并链接到这一页。

## 整理层

每个模块一页，页里按小板块分 `##`：

| 页面（主题编号） | 小板块 |
|---|---|
| 公司概况（company） | 公司介绍、发展历程、主要业务、公司能力、公司优势、生产设备与工艺、质量保证、资质认证、销售市场 |
| 产品总览（products） | 每条产品线一节：每本画册、每个官网大类，其他产品资料合成一节 |
| 产品大类页（cat-…）或产品系列页（line-…） | 产品介绍、特性和优势、参数、应用 |
| 解决方案与定制服务（custom） | 应用场景、行业解决方案、定制服务类型 |
| 合作案例（cases） | 客户案例、项目案例、用户评价、订单成果；只用已生效的资料，案例通常要等客户确认 |
| 行业知识与洞察（fabric） | 行业介绍、产业链、专业术语、技术知识、市场趋势 |
| 常见问题（faq） | 产品问题、定制与打样、生产与交期、质量与认证、包装与运输 |
| 服务与其他（other） | 服务政策、包装运输、安装维护、资料下载 |

产品大类页：官网至少有 3 页产品页的大类各一页。产品系列页：每本有效的产品画册各成一页“产品系列-<画册名>”，有没有官网都一样；配置的 `topics` 里已经写了同编号的系列页时，不再重复加。

**页面不串内容：**
- 官网产品页只进它自己大类的页面和产品总览，不进其他大类页，也不进公司概况、解决方案这些页。官网产品标题里常有 “Factory Direct… OEM” 这类词，不挡住就会把同一批产品页塞进每一页。
- 大类页从别的资料取原文时，要命中完整的大类名（“Tapestry Bag”），不是第一个词（“Tapestry”）。

**文件名固定为“类别-名称”：**公司-概况、产品-总览、产品大类-<大类名>、产品系列-<画册名>、解决方案-定制服务、案例-合作案例、行业-知识与洞察、FAQ-常见问题、其他-服务与其他；单独成页的小板块是“<父页类别>-<小板块名>”。页面里的 `#` 标题可以写得更详细，不影响文件名。官网大类名是英文时，登记 MAT“官网大类还没有中文名”，在 `categories` 里补上。

- **小板块分类表**在 `assets/sections-default.json`：每个小板块有中英文关键词和“怎么补”的建议。
  - 分类由脚本按关键词做，不花 token。
  - 一段原文归到命中关键词最多的那个小板块。
  - 本模块自己的资料命中 1 个就算；别的模块的资料要命中 2 个，公司概况例外（画册开头常有一句公司介绍）。
  - 本模块资料里一个关键词都没命中的段落，归到第一个小板块，比如“公司介绍”“产品介绍”。
  - 客户自己的调整写在 kb-config.json 的 `sections` 里，见上面的配置说明。
- `curate.py prepare` 按主题挑出“有效”或“部分待客户确认”文档里的保留块和标记块，去重后按小板块分组写进 `input.md`：
  - 每个小板块最多 40 块，产品总览每条产品线最多 30 块，一个忙的小板块占不满整页。
  - 先放已写好的 `page.md` 引用过、而且还能用的块，重跑不会把它们挤掉。
  - 其余按文档轮流取，T1 在前，一份很长的文档不能占满名额。
  - 一个小板块去重后超过 120 段时，单独成页（主题编号 `<父主题>-<小板块>`，最多 150 块）。原页的 input.md 里标“单独成页”，生成时原页末尾自动加“另见”链接。
  - 按 `style_prefixes` 从原文抽出款号，写进 `topic.json`。
  - 本次的主题清单和每个小板块的原文数写进 `curation/topics.json`；没有原文的主题也列出来，供缺口页用。
- AI 按 `README.md` 写 `page.md`。标题以 `page.md` 的 `# 标题` 为准，文件名也跟着它。每个小板块写成 `## 小板块名`，名字和 input.md 里一致，下面可以再分 `###`；原文不够的小板块不写。
- `curate.py check` 逐行核对：
  - 每条要有 `{{src:块编号}}`，编号必须属于本主题。引用的原文已删除、被拦或所在文档不再有效时，报“原文已不可用”，指出要改的行。
  - 数字、百分比、克重、年份、款号要在引用的原文里出现。
  - 引用了 ⚠ 原文的行必须带 ⚠。
  - 不能出现价格、条款等禁止内容。
  - 写全：一页引用到的资料要有 input.md 里资料的一半以上；产品总览要写到每一条产品线。不够时报“只写到 n/m 份资料”，列出没写到的资料。核对结果里的 `coverage` 记着两个数。
- 流水线里的 `curate.py build` 只发布通过核对的页面：
  - 出处换成 `[[来源文档#段落|〔n〕]]`，`{{款号表}}` 换成脚本抽出的款号及出处。
  - 末尾列出用到的来源。
  - 引用都来自无标记的 T1 时公开性为 public，否则为 internal。
- 有页面没通过核对时，校验失败。
- 写了一部分主题、其余没写时，校验失败（没有原文的主题不算）；不写的主题要在配置的 `skip_topics` 里写理由。一页都没写时只提醒，因为可能还没开始整理。

## 各类文件怎么读

| 文件 | 怎么读 | 读不全时 |
|---|---|---|
| PDF | 装了 PyMuPDF：记下每行文字在页面上的位置，按“上到下、左到右、分栏”排。一栏单独成一段，定位写 `page 3`、`page 3 col 2`，都归在“第 3 页”下。款号在哪一栏上方就和那一栏的特点同段；原件没写款号的栏就没有款号。没装 PyMuPDF：用 pypdf 按存储顺序读 | 文字少于 20 字的页记为“待识别页” |
| PPT | 读每个文本框和表格的位置，按同样的规则分栏，定位 `slide 2`、`slide 2 col 2`。演讲者备注单独一节“第 N 张幻灯片备注”。每张幻灯片附原图，见“来源层” | 只有图片、几乎没字的页记为“待识别页” |
| Word | 正文和表格按文档顺序读 | 嵌在 Word 里的图片暂不识别 |
| Excel | 见“表格规则” | 找不到表头的表登记 MAT |
| 图片 | 不直接读 | 走 MinerU 或 AI 读图 |

旧版提取结果会自动重读：某种文件的读法变了以后（`extract-status.json` 里这类文件的 `extractor` 版本更低），只重读这类文件；比如 PDF 读法变了，不会让所有老 .xls 再过一遍 LibreOffice。

**老格式 Office（.xls/.doc/.ppt）用 LibreOffice 转换：**
- 提取开始前先试转一个小表格；转不了（没装、沙盒不让写文件）就不转了，这些文件标 `needs_libreoffice`，并提示用不受沙盒限制的方式重跑、在本机终端运行，或另存为新格式。
- 每次转换用一个新的配置目录，放在短的英文路径下；一次崩溃只影响这一个文件。
- 每个文件最多 2 分钟，超时就结束 LibreOffice 的整组进程，不重试；没生成文件的重试一次。连续 3 个文件失败，其余的不再尝试。
- 转换一个接一个地做，每个文件打印一行进度。
- 转好的文件按哈希存在 `04_知识库构建/converted/`，抽图片时直接用，转换失败过的文件抽图片时不再重转。

**看图核对（有文字的页也要对照原图看）：**文字层可能漏了图片里的款号和产品名，字体坏了会读出乱码，一页多款时也看不出款号对应哪款。`page_check.py` 把这些页挑出来，让 AI 对照原图看。
- 挑哪些页：T1/T2 的 PDF、PPT 里，有成块图片且文字少于 400 字的页；图片张数多于找到的款号数的页；文字里有乱码的页；Word（.docx/.doc）里大于 15 KB 的图片；其余页随机抽一成，每份至少一页。完全没字、还没人读过的页不在这里，归“待识别页”。
- **按处理方式：**一类文件的处理方式是“MinerU 初稿 + AI 复核”或“AI 看图复核”时（用户看样例后选，存在 `sample-decisions.json` 的 `method`），这类每一页有成块图片的页都列出来，不只挑上面几种。选了 MinerU 的，等这份的 MinerU 初稿出来才列（`plan.json` 的 `skipped` 写“等 MinerU 初稿”）。
- `plan` 由流水线自动运行：把挑出的页画成图（100 dpi），和这一页**现在的初稿**一起写进 `04_知识库构建/page-check/todo.jsonl`，附规则 `README.md`。初稿是文字层，加上 MinerU 识别、AI 读图读出的内容，各段标【MinerU 识别】【AI 读图】；`draft` 记初稿来自哪里。已经核对过的页不再列出；核对时还没有 MinerU 初稿、后来有了的页，再列一次。没装 PyMuPDF 时不做，校验给提醒。
- AI 每页回答四项：`missing`（图上有、文字里没有的内容，逐字照抄）、`text_errors`（文字哪里和图上不一样）、`pairing`（一页多款时每款对应哪个款号）、`unclear`（原件本身看不出对应）。
- `collect` 之后：
  - `missing` 作为这一页的补充文字（定位 `page N check`，`engine: ai`，`checked: true`）存进 `mineru-units/`，标 ⚠“AI 看图补充，待核对”，登记 ANM。定位和 MinerU 的 `page N ocr` 分开，MinerU 读过的页上补的字和 MinerU 的内容并排保留，不会被 MinerU 覆盖。
  - `text_errors` 在这一页标 ⚠“以原图为准”，登记 MAT“提取文字和原图不一致的页”。原文和 MinerU 初稿都不改，人对照原图定。
  - `pairing` 作为这一页的核对说明写在页标题下；`unclear` 的页标 ⚠“不要自行配对”，登记 CUS“款号和产品对应不清楚”，问客户。
  - 说明里带价格、条款等禁止内容时不写。
- 核对结果存在 `page-check/results.json`，发布时存进知识库，重建时直接用。
- 校验：挑出的页还有没核对的、又已经核对了一部分时，校验失败；一页都没核对时只提醒；配置里写 `"page_check": {"skip": "理由"}` 可以不做。

**表格和流程：**格式可以整理，字一个不改、不加。
- PDF：装了 PyMuPDF 时先找表格（至少 2 行 2 列、一半以上的格有字，画册页上的分隔线不算），表格按行整理成 Markdown 表，定位 `page N table K`，归在“第 N 页”下；表格以外的部分照旧分栏读。
- Word：表格按行整理成 Markdown 表，第一行当表头；单元格里的竖线换成全角“／”。用旧版本提取的“a | b”行，生成净化原文时也整理成表。
- MinerU：识别出的表格 HTML 转成 Markdown 表，不再把单元格挤成一行。
- 一张表里有一行因为报价被删时，剩下的行仍排在同一张表里。
- 校验对普通资料里的表格不套用产品表的行规则（数量、包装、业务备注），只对产品表和报价单套用。
- 看图核对时，AI 还要说这一页是什么结构（表格、流程图、时间轴、地图、图表），并按原结构排好图上的字：表格写成 Markdown 表，流程图按箭头顺序编号，时间轴按时间先后编号。脚本逐词检查都在这一页的文字里，有图上没有的词就整段不收。收下的写在页标题下，标 ⚠“看图整理，AI 整理，只用了图上的字”。

**待识别页怎么补：**
1. 首选 MinerU（要用户批准外发），见“MinerU”。
2. MinerU 用不了时，用 AI 读图：
   - `ai_read.py export --out <运行目录> --package <初筛包>` 把所有待识别页、待识别图片画成图，写进 `04_知识库构建/ai-read/`，附读图规则 `README.md` 和清单 `todo.jsonl`。
   - AI 逐张看图，按规则逐字转写，写 `answer-*.jsonl`。
   - `ai_read.py collect --out <运行目录>` 校验后存进 `mineru-units/`，每页标 `engine: ai`，再重跑流水线。
   - 转写内容入库时标 ⚠“AI 读图转写，待核对”，登记 ANM；整理页引用时也要带 ⚠。
   - 看过、确实没字的页记为已读，不再列为待识别。
   - 图片不出本机，由正在工作的 AI 读。之后 MinerU 读到的页会替换 AI 转写，AI 读过而 MinerU 没读到的页保留。

## 表格规则

- 表头以上的行全部丢弃，其中的文字进入客户名字典。
- 一列要同时满足“表头被识别为产品字段”和“不在清理定位里”才保留，模板判断结果优先。
- 工作表名发布时统一写成“表 1”“表 2”；隐藏工作表不入库。
- 同一款号在多张表里面料说法不同时，产品主档并列保留，登记 CUS 问客户。
- Excel 里的 `_xHHHH_` 转义（比如 `_x001f_`）要在提取时解码成对应字符；控制字符直接去掉。
- 不带工作表名的列定位不用于其他表。
- **初筛标的清理位置只当参考，不照单执行**（任何文件都一样）：
  - 删不删由整理时的实际内容决定：表头说明一列装的是什么，行规则逐格查价格、成本、数量、客户和报价条件。初筛没标的地方照样查。
  - 初筛标了、但表头是产品字段（款号、品名、描述、面料、尺码、图片）的列，保留；落在表头以下的数据行，保留。保留的行旁标 ⚠“初筛建议删除（原因），整理时判断保留”，表格下面写明，登记 MAT“初筛建议删除、整理时判断保留的内容”。确实该删的，在 `review-decisions.json` 的 `drop_blocks` 里写块编号。
  - 初筛的标记不再决定表头在哪一行：标的范围多划了一行，也不会把整张表弄丢。
  - 初筛写的位置找不到时，文件不再整份暂缓，照常按表头和行规则清理后入库，登记 MAT“初筛写的清理位置找不到”。
- **产品表以外的 Excel**（A 类、没有产品表头的 B 类、客户回复“保留”的 D 类）：每张可见的表按人读的样子排，不显示单元格坐标，字一个不改：
  - 小标题是“表 n · 工作表名”（比如“表 1 · 会议一体机”）；工作表名里有客户名或禁用词时（筛查认出的），只写“表 n”。
  - 表头行是第一行有 3 个以上、且不少于最满那行六成的格子、下面还有数据行的行。表头上面的行（公司名、地址、Quotation、客户栏）写成普通文字；最后一行数据下面的行（备注、条款、签字）也写成普通文字。
  - 表格里，表头以下整列都空的列不放进表，在表下面写一行“原表还有这些列，下面没有内容：……”。纵向合并的格子，把值填到它覆盖的每一行。格子里的换行写成 `<br>`。紧跟在“date / 日期”后面的 Excel 日期数字写成日期（46148 → 2026-05-06）。
  - 找不到这样的表头行时（比如第一行就是表头的普通清单），整张照原样成一张表。
  - 隐藏的表不入库。这类表按普通资料的规则删报价金额和客户信息，不套用报价单的删列规则。
- **报价条款**：英文付款条款（Payment term:、Advance payment 20%、30% deposit、80% before shipment）和贸易条款（Price term:、EXW、FOB、CIF、CFR、DDP、DAP）在所有资料里都删，删到所在的那一句或那一行。
- **先分表型：**表头里有单价、报价、数量、金额、MOQ、起订这类列的是报价单，其余按产品清单处理。报价单标题写“报价单-<哈希>”，放进 `产品表/报价单/`。
- **序号列不是款号：**“款号”列里全是 1、2、3 这种 1–3 位数字时，那是报价单的行号，去掉；去掉后只剩图片、没有描述和面料的行不入库。
- 所有保留下来的行再合成一份 `产品表/00_产品表汇总.md`，见“来源层”。
- 内容完全相同的另存副本只发布一份。

## MinerU

- 首次设置：每台电脑运行一次 `scripts/setup_mineru.cmd`。Token 存在 Windows 用户环境变量里，和 manage-article-knowledge 共用。
- `probe` 只看本机；`health-check` 上传不含客户信息的测试 PDF，本月通过后不重复消耗额度。服务端可能提前让 Token 失效，以在线检查为准。
- `mineru_ocr.py plan` 列计划；`run` 只在有批准记录时上传，结果按文件哈希缓存，按页存成 `page N ocr`。
- **计划里有什么：**用户看样例后给这类选了“MinerU 初稿 + AI 复核”的全部文件；还有没人读过的无文字页的文件；整份读不出文字的文件。画册不再因为是画册就自动上传。
- **样例试读：**`plan --samples` / `run --samples` 只列、只传各类还没定处理方式的样例，给用户看 MinerU 的效果再选；《处理计划与样例》的“样例情况”会写 MinerU 比文字层多读出了几页。同样要批准上传。
- 识别结果长期存进知识库的 `02_源资料/20_MinerU按需提取/`：
  - 每份文件一个 `<来源文档标题>.md` 给人看，按页分段，开头写来源文件、识别日期、页数。
  - 同名 `.json` 给脚本用，里面是按页的文字。
- 重跑时先读这里；有结果就不再上传。
- 识别出的文字只补原文字层没有的行，英文词照样检查是否核实过。

- 网址第一段决定模块和大类；网址有两级时按产品页处理。

- JS 页面用浏览器读取后保存成 `{"url", "title", "blocks": [{"tag", "text"}]}`，再导入。

## 素材图片

**从哪里来：**
- 报价单、产品表行里嵌的图（每行最多 2 张）。
- 画册等 PDF 里印的照片：用 PyMuPDF 取原图，短边小于 300 像素或小于 15KB 的不收（图标），同一张图出现在 3 页以上的不收（logo、底图）。每份最多 400 张。整页有删除或待客户确认内容的页不收。
- 官网页面上的图：`fetch_website.py` 读页面时一并下载，只下官网自己的域名和子域名，jpg/png/webp，大于 15KB，每页最多 12 张，一次最多 800 张；客户案例页不下。出现在 3 页以上的不收。`--no-pictures` 只读文字。
- 整页截图（来源卡片上的原页图）。

**命名：**“类别-标签-8位编号.扩展名”。编号取自图片内容的哈希，保证不重名。标签只取图片旁边的原文：
- 表格行：本行的品名；没有品名时用款号栏里不带数字的词。符合 `style_prefixes` 的公司款号保留。
- 画册：页上第一行短标题，加这一页唯一的公司款号；类别是画册系列名。
- 官网：图片的 alt；alt 是空的或是相机文件名（IMG_0042.jpg 这类）时用页面标题。
- 带数字的词除非是公司款号都去掉（买家款号）；命中客户名、禁用词的，或所在原文标 ⚠ 的，不取标签，名字只有编号（“编号”名）。
- `pictures.py export/collect` 让 AI 给“编号”名的非内部图片看图起名：只写看得见的内容；看到人物、客户标志、价格的写“不用”，这张图不进素材。AI 起的名字标“AI看图”，能否用于官网降为“待核对”。

**文件夹：**`产品/<官网大类或画册系列>`、`资料包素材/<大类>/<产品>/<图片类型>`、`工厂与设备`、`证书`、`公司`、`报价单参考图`、`产品表图片`、`页面图`。证书、工厂按图片说明和页面文字里的关键词分。

**能否用于官网：**
- 可用于官网：官网页面或公司画册，资料“有效”、不是参考稿，所在原文没有 ⚠。
- 待核对：原文有 ⚠，或名字是 AI 起的。
- 内部：报价单和产品表里的图（多是买家询价发来的款式），整页截图。内部图片不给英文文件名。

**名字不变：**给过的名字写进 `picture-names.json`，以后一直用；只有“编号”名在有了原文或 AI 名字后会换。发布时 `90_素材` 里以前发布的 `img-<编号>` 文件移到新名字，版本说明记“旧路径 → 新路径”；库里不是本次发布写的页面（文章草稿、人写的笔记）里的旧图片名，按文件名替换成新名。

**索引：**`90_素材/00_素材索引.md` 按文件夹分节，每张图一行：说明（可当 alt）、能否用于官网、名字来自（原文、AI看图、编号）、第一次出现的资料和位置，多处共用写“等 N 处”。不嵌缩略图，几千张图时 Obsidian 也能打开。`90_素材/00_素材清单.csv` 是同样内容的表格，多一列英文文件名建议，给建站的同事用。

**校验：**图片的名字和说明也按禁用词、客户名检查，命中就不通过。

**初筛按文件夹保留的图片和视频（建站资料包）：**
- 初筛对整理好的文件夹（产品渲染图、白底图、宣传视频等）抽看样本后整批归 A，manifest 里带 `folder_rule`。这类图片和全部 A 类视频、音频走 `media` 路线，不当文档读，也不逐张问客户。
- 图片：可用的、不超过 `--max-image-mb`（默认 5MB）的，按内容哈希复制成 `img-<编号>`，进 `90_素材/资料包素材/<大类>/<产品>/<图片类型>/`（认不出产品的进原来的文件夹最后三层），名字是“产品名（或上一层文件夹）-原文件名-8位编号”，能否用于官网写“可用于官网”。文件夹名或文件名命中客户名、禁用词时，文件夹换成“其他”、名字只留编号。
- 视频、音频和超过大小的图片不复制进知识库，原件留在初筛包。《素材索引》最后一节“留在初筛包里的素材”按原文件夹一行，写有几个、状态（已保留，内容待转写／图片较大）和“打开文件夹”链接。视频转写以前不出知识点。
- 初筛标了整个文件夹待客户确认的（`review_group`，常见于客户现场照片）：登记一条 CUS，客户确认表只有一行，写文件夹名和文件数、初筛写的问题；`apply_answers.py` 把回答用到文件夹里每个文件。回复前这些图片不进素材，在索引最后一节写“待客户确认（整个文件夹）”。
- 初筛包的《知识库文件对照》里，这些文件的去向写“进素材库：90_素材/…”“视频或音频，原件留在初筛包”或“整个文件夹待客户确认”。
- 没有 `folder_rule` 的单张 A 类图片照旧：走 MinerU 或 AI 读图，读出文字后入库。

## 建站资料视图

`03_正式知识/80_建站资料/`，`site_view.py` 在每次 `render_kb.py` 时生成，只提取了一部分时也生成。页面名都以“建站-”开头，不和整理页、来源层重名。

- **栏目**（中英对照）：首页 Home、关于我们 About Us（企业介绍 Company Profile、工厂与生产 Factory、研发 R&D、资质认证 Certificates、展会 Exhibitions 五个子页）、产品 Products、解决方案 Solutions、服务 Services、案例 Cases、资源中心 Resources、博客 / 新闻 Blog & News、FAQ、联系我们 Contact Us、待归类 To Sort；总览页 `00_建站资料总览.md`。
- **产品**：初筛包里 `产品`（或 `产品资料`、`products`）文件夹下按层级：大类 / 小类 / 产品。说内容的文件夹（白底图、实拍图、规格书、英文版、“1.上架推广资料”）不算层级。末尾是批次号的（“DS50系列1”“DS50系列2”“第二批”“(2)”“新版”）合成一个产品，页上写“客户分 N 批给的资料”；字母后直接跟数字的是型号（DS20），不算批次。全是数字的文件夹（01–11）看不出是型号还是批次，列在总览“要人确认的”。kb-config.json 的 `products`（`name`、`category`、`sub`、`aliases`）优先于文件夹名。小类名、产品名和其中的型号码（DS50）也用来把产品文件夹以外的东西找回这个产品：别处的规格书、官网截图文件夹、官网页面；在路径里越深的文件夹越优先，同一层取最长的名字。
- **人指定栏目**：kb-config.json 的 `site_sections`（栏目编号 → 文件夹名或标题列表），按完整名字对上的先算，优先于栏目规则和产品名。
- **其他栏目**：按文件夹名、文件名、标题里的词，依次判断首页、案例、解决方案、服务、FAQ、博客、联系我们、关于我们的五个子页。画册和名字里有规格书、说明书、catalog、spec、manual 的文档另外列进资源中心（同一个文件，两处都是链接）。都对不上的进待归类，写原因。
- **每页**：进度一行；已处理的文件（净化原文、打开原件、状态、来自哪个文件夹或批次）；官网页面；图片按类型分节（每类显示前 8 张，其余列链接，附原图所在文件夹）；视频（封面、大小、时长、打开）；相关但还没处理的文件（等样例确认后提取、初筛待定、读不出文字、图片还没识别、整个文件夹待客户确认，最多列 200 个）；还缺什么（产品页：白底图、实物图、规格书、视频；关于我们：介绍文字、工厂照片、证书图片等）。报价单图片和整页截图是内部材料，不进这个视图；E 类排除的不出现。
- **FAQ**：没有 FAQ 文件也保留，列出“待补充问题”（客户确认表里的问题）。
- **首页候选**：`site_view.py home-candidates export` 从产品主图、白底图、效果图里列候选，AI 挑后 `collect` 存进 `site-home.json`（发布时存进知识库）；页上标“候选，待确认”，人把 `confirmed` 改成 `true` 后标“已确认”。
- **隐私**：路径或文件名里有客户名、禁用词的，不显示原名、不给链接，写“见对照表”。
- 案例图片可以直接公开使用，不另外标。

## 维护

| 触发 | 做法 |
|---|---|
| 运行目录已经删了 | 用 `--package <初筛包> --vault <项目目录>` 重建，从知识库恢复配置和各种判断 |
| 来了新资料 | 先筛成小初筛包，加一个 `--package` 重跑 |
| 客户回复确认表 | `apply_answers.py` 读回，再重跑、发布；“以哪个为准”这类回答只记备注 |
| 客户先填了初筛包的确认表 | `apply_answers.py --answers <初筛包>/客户确认表.xlsx`，再建库；初筛包不改 |
| 官网一个月没读 | 重跑 `fetch_website.py` |
| 词表或规则更新 | 直接重跑 |
| 每月 | `kb_status.py --monthly` 更新总览，写体检报告 |

## 和 manage-article-knowledge 一起用

- 建库以本 Skill 为准，不需要先装 manage，也不需要先跑它的初始化。
- 台账只有一套：本 Skill 的 CUS/MAT/ANM 台账就用 `01_<名称>.md` 这个名字。库里已有别的工具建的同名空模板（一条记录也没有）时，发布时把模板移进 `60_版本归档`，由本 Skill 的台账接管；以前因此写成 `02_知识库构建_<名称>.md` 的，发布时改回 `01_` 名字，人填的阶段和处理记录都保留。
- 别的工具的同名台账里已经有记录时，不动它，本 Skill 的台账仍写成 `02_知识库构建_<名称>.md`。
- 它的来源索引要求“客户原始资料路径”在项目之外，指向初筛包时会读到包里的排除类资料。要用它的索引，先给它配好排除清单，只放行 A 类和清理后的资料。
- `--manage-skill` 是可选项：加了才会在发布后顺带运行它的索引和校验，平时建库不用加。
- 写文章时由 manage 按需建 Claim；整理页和来源层都不等于已核验的 Claim。
