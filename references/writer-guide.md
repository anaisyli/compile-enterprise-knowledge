# 写作方接入说明（写作 Skill 每次写文章时读这一页）

给写作 Skill 用的唯一规则来源。写作 Skill 自己只保留一小段“知识库接入”，指向这一页；这里改了，各写作 Skill 不用重改。本页只管怎么从知识库取资料、怎么用、写完怎么核对，不管选题、文风、SEO/GEO、图片和交付——那些照各写作 Skill 原来的流程。

下面的命令都在 compile-enterprise-knowledge 的 `scripts/` 目录运行；`<知识库>` 是本次客户的知识库项目文件夹（里面有 `01_工作台`、`03_正式知识`）。

## 什么时候用这一页

客户知识库的 `01_工作台/写作目录.md` 存在时用这一页。没有这页时，知识库还没按新流程发布，按写作 Skill 原来的方式读资料，并提醒用户让知识库负责人发布一次。用户明确要“严格模式”“逐句核验”“算引用率”时，改用 manage-article-knowledge，不用这一页。

## 一、范围锁

- 每次只用当前请求指定的那一个客户知识库；不搜索、不读取别的客户的知识库或旧对话里的路径。
- 知识库是只读的：除了下面第四步的外部调研命令，不创建、不修改知识库里的任何文件。

## 二、先定大纲，再取资料

1. 按写作 Skill 原来的流程定选题、标题、关键词和大纲。大纲按读者需要定，不先看知识库有什么再删章节。
2. 读 `<知识库>/01_工作台/写作目录.md`（或运行 `python kb_lookup.py catalog --vault "<知识库>"`），对着大纲逐节挑要用的“页名#小板块”或“页名#小板块 > 子节”。英文大纲对中文小板块由你判断；页名可以写文件名、标题或别名。
3. 目录里找不到资料的大纲节，记成“缺口”。

## 三、取资料包

```bash
python kb_lookup.py pack --vault "<知识库>" --sections "页名#小板块;页名#小板块 > 子节" --gaps "缺口一;缺口二" --output "<本篇工作目录>/资料包.md"
```

- 资料包放在本篇自己的工作目录（写作 Skill 的输出目录），不要放进知识库或客户原始资料目录。
- 超过 25 行的表默认折叠成“表头 + 行数”，后面附一条补读命令。**文章要写这张表里的具体数值**（某个口径的尺寸、扭矩、流量、压力、规格对照）时，必须先运行那条命令补读整张表（存成 `资料包-补读.md`、`资料包-补读2.md`……），只写表里有的数；只是提一句“提供完整尺寸表”不用补读。
- 超过 1.5 万字时开头会提示，先少挑几个小板块再取一次；实在都要，加 `--budget 15000`：脚本只做不丢事实的压缩（超过 10 行的表也折叠、去掉“原文里搜到的”线索），客户事实、外部知识和口径避坑一条不删。
- 输出里“缺口”一节列出挑错的页名或小板块，改了再取。

## 四、缺口怎么办

资料包“四、缺口”给每个缺口一个判断：

| 判断 | 怎么办 |
|---|---|
| 外部公共知识里已有 | 已放进资料包第二部分，直接用 |
| 客户专属（产能、证书、案例、交期、MOQ、价格、保修等） | 不外部调研；文章里中性表述或不写；需要时在交付说明里列出“要问客户的” |
| 公共知识 | 可以外部调研（每篇最多 2 个）：见下 |

外部调研（只查行业公共知识）：

1. `python research.py plan --vault "<知识库>" --from-outline "缺口一;缺口二" --article "<标题>"`
2. 按它返回的 `README.md` 调研，把结果写成 `answer-*.jsonl`，再 `python research.py collect --vault "<知识库>"`；有 `failed` 就按原因改完再 collect。
3. 重新运行第三步的 `pack`，新资料会出现在第二部分。
4. 调研查不到可靠来源就写 `not_found`，这一节按“没有资料”处理，不要凑。退出码 3 表示另一台电脑正在写知识库，稍后再试。

## 五、写的时候

1. **速查卡和第一部分（客户专属事实）**：可以代表公司写。公司、产品、型号、参数、认证、案例、能力和承诺，只能用这里有的；不扩大范围，不补数字。
2. **第二部分（行业公共知识）**：只作背景、原理和论据，不能写成客户的能力、承诺或认证（“行业普遍做法”不等于“我们能做到”）。
3. **第三部分（口径避坑）**：这些说法有冲突或待核实，不要写成确定的事实，不写里面的具体数字；需要时用中性说法，但中性说法也不能编出资料里没有的新事实。
4. **“原文里搜到的”**：还没整理、没人核对过，只能作线索；要用其中的客户事实，先请知识库负责人整理进知识页。
5. 资料包里没有的公司事实不要编，也不要凭模型记忆补。通用的行业常识、原理和写作上的过渡可以自由写，但不能产生新的客户参数、型号结论、认证、案例或承诺。
6. 正文里不提知识库、资料包、来源文件、调研过程，不写“according to the catalog”这类来源说法，不复述〔n〕和页名。
7. 不写竞品品牌、型号、价格和比较结论。

## 六、写完核对（必做，几秒钟）

```bash
python check_article.py --article "<终稿 .md / .docx>" --pack "<本篇工作目录>/资料包.md" --pack "<本篇工作目录>/资料包-补读.md" --vault "<知识库>" --output "<本篇工作目录>/核对提示.md"
```

补读过的每个资料包都用一个 `--pack` 带上，不然补读表里的数会被报成“资料包里没有”。它把文章里的型号、标准号、认证、规格、带单位的数字、编号（材料牌号等）和年份逐个到资料包里找；认哪些写法按客户所在行业和这个客户自己的资料自动定：

- **资料包里没有**：改成资料包里的说法、改写成通用表述，或删掉；标了“知识库别处出现过”的，确认是同一个产品后补取那一节再改。
- **只出现在口径避坑 / 原文里搜到的**：按第五步 3、4 改。
- **竞品名称**：删掉。

改完再跑一次。还剩下的、确实要保留的，把《核对提示》里的条目附在交付说明里。这一步只提醒，不挡交付。

## 七、交付

照写作 Skill 原来的交付流程。交付说明里写：用了哪些小板块（资料包开头的列表）、调研补了哪些缺口、哪些“要问客户”、核对提示还剩什么。
